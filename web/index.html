Desktop and CLI in one session

See what your script does.

Connect a script or coding agent to a named desktop session. The app shows camera activity, saved files and errors.

# Open a named desktop session
capturefab gui --name bench

# Use another terminal for these commands
capturefab --session bench connect sim:0
capturefab --session bench --camera sim:0 capture -o shot.png
capturefab --session bench status --json

Capture with clear limits

Keep control of files and storage.

Each camera runs in a separate process. Live previews use the newest frame. Capture and recording use storage limits.

Read about the architecture →
Protect existing files
Capturefab does not replace an existing file when its name matches the output name.
Set storage limits
The defaults are 10 GiB and 10,000 files. Capture stops at the limit. Automatic deletion is optional.
Run locally
Capturefab has no telemetry or automatic update requests. You can capture camera images without a cloud account.

Before you download

Which cameras can I connect?

Capturefab supports GigE Vision, USB3 Vision, host cameras, network streams and other sources. Support depends on the device and operating system. This is an initial implementation with less feature coverage than some vendor SDKs. Read the connection guide and camera compatibility notes for device requirements.

Must I install a vendor SDK or FFmpeg?

No. Published downloads include FFmpeg for host cameras, streams and video encoding. You must supply the operating system's graphics, USB and camera drivers. USB3 Vision cameras on Windows must have WinUSB. Read the installation instructions.

Can I use Capturefab for commercial work?

Yes. Capturefab uses the MIT license. The separate FFmpeg executable uses GPLv3. Each release includes the corresponding source and license notices. Read the licensing details before redistribution.

Can a script control an open desktop session?

Yes. Camera commands automatically use the only desktop or headless session that is open. Use capturefab sessions to list sessions. Use --session NAME to select one when several sessions are open. Read about sessions and automation.

What occurs at the storage limit?

Capturefab stops capture or recording. It returns exit code 6 and a message that identifies the limit. Capturefab disables automatic deletion by default. Use --delete-oldest to enable retention. Retention applies only to files that Capturefab created and whose checksums still match.

How do I verify a download?

The download selector shows a SHA-256 command and the correct checksum. Run the command for the downloaded file. Compare its result with the correct checksum. The full download list also includes checksums. You can verify GitHub build provenance with gh attestation verify FILE --repo capturefab/capturefab.

Build Capturefab from source

Build requirements

Use a stable Rust toolchain, a C compiler and CMake. For x86 builds, NASM is also necessary for libjpeg-turbo. FFmpeg is necessary for webcams, streams and recording. Read the build guide for configuration.

git clone https://github.com/capturefab/capturefab
cd capturefab
# Desktop app and CLI
cargo build --release
# Headless CLI
cargo build --release --no-default-features --features usb,jpeg
target/release/capturefab --camera sim:0 capture -o first.png
