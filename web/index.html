02 / Capture

A few commands to a frame.

Open the GUI

Launch the workbench, discover cameras, and connect to a preview.

capturefab

Discover cameras

Get structured discovery results for scripts and tools.

capturefab discover --json

Read, configure, capture

Use a discovered ID, unique serial, or a GigE camera's IP address. Feature names vary by camera; features shows the available controls.

capturefab --camera 192.168.1.10 features
capturefab --camera 192.168.1.10 get Width Height ExposureTime
capturefab --camera 192.168.1.10 set ExposureTime=5000
capturefab --camera 192.168.1.10 capture -n 10 -o frames

Open a network stream

Use a stream URL directly, or resolve an ONVIF camera's profiles.

capturefab --camera 'rtsp://camera/live' capture -o frame.png
capturefab onvif discover --json
capturefab --camera 'onvif:http://camera/onvif/device_service' capture -o onvif.png

Use a host camera

List cameras managed by the operating system, then use its native locator.

capturefab native --json
# macOS
capturefab --camera avfoundation:0 capture -o webcam.png
# Linux, including driver-backed USB or CSI cameras
capturefab --camera v4l2:/dev/video0 capture -o webcam.png
# Windows
capturefab --camera 'dshow:video=Camera Name' capture -o webcam.png
Forward a camera to MediaMTX or an NVR

Publish to an existing RTSP server, SRT endpoint, or a local video file. Automatic encoder selection probes usable hardware and falls back to software.

capturefab --camera 192.168.1.10 forward \
  --output rtsp://localhost:8554/camera \
  --encoder auto --fps 30 --bitrate 4M --duration 60

03 / Automate

Keep the session. Hand over the controls.

The GUI exposes a local session. Shell scripts and coding agents can inspect it, connect cameras, change features, and capture frames while the window stays open.

capturefab sessions --json
capturefab --session gui status --json
capturefab --session gui connect 192.168.1.10
capturefab --session gui set ExposureTime=5000
capturefab --session gui capture -n 10 -o frames
capturefab schema --json

Unix conventions. Structured results on stdout; diagnostics on stderr. Exit codes, pipes, native shell completions, and foreground headless sessions.

Agent readable. A versioned schema and local session API, plus instructions for Claude Code, Codex, OpenCode, and other tools that can invoke a CLI.

04 / Platforms

A workbench, wherever the camera is.

  • macOSApple Silicon and Intel. Native cameras through AVFoundation.
  • Windowsx64 and ARM64 targets. Native cameras through DirectShow.
  • Linuxx64, ARM64, and ARMv7 targets. Native USB and CSI cameras through V4L2 drivers.
  • Pi & JetsonUse the Linux build matching the installed OS architecture. Headless builds suit remote capture.

The GUI uses GPU rendering. Video decoding and forwarding can use hardware acceleration when the selected build, driver, and device support it; automatic encoder selection tests the hardware and falls back to software. NVIDIA, Apple, AMD, Qualcomm, and ARM capabilities vary by platform.

Transport, codec, operating system, and hardware coverage vary by build. See the release assets and validation record for tested combinations. USB permissions and host camera drivers come from the operating system.
