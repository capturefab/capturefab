Commands, options and automation

Find a command, its inputs and its limits. For step-by-step tasks, open the user guide.

How to use commands

Run commands from a terminal or an external agent.

Start with capturefab COMMAND --help. Use capturefab COMMAND SUBCOMMAND --help for a nested command.

Running capturefab without a command opens the desktop app. Other commands do not open it.

Camera commands use the only running session automatically. With multiple sessions, select one with --session NAME.

Where supported, a camera command can use a temporary worker when no session runs. Use --direct --camera ID to choose this explicitly.

Local output paths belong to the calling terminal. Named destination paths belong to that destination.

Use one number and unit for durations, such as 30s, 5m or 1.5h. File sizes accept values such as 512MiB and 2GiB.

capturefab gui --name bench
# Run subsequent commands in another terminal:
capturefab --session bench connect sim:0
capturefab --session bench --camera sim:0 capture -o shot.png
capturefab --session bench status --json

JSON and errors

--json returns one {version, ok, result} object, or {version, ok, error} on failure.

Progress and diagnostics go to stderr. Read error.code before deciding whether to retry.

Exit codeMeaning
0Success, including a closed stdout pipe
1Operation or input/output failure
2Invalid arguments or input
3Camera or session unavailable
4Timeout
5Unsupported feature or format
6Storage quota or disk full

For assistant run, exit 0 can also mean needs_user. Read the result before treating the task as finished.

A request timeout can occur after the session accepts a command. Read status before sending the same write again.

Installed builds can have different optional features. Use doctor --json, schema --json and installed help to confirm availability.

Capture images and manage schedules

Save images now or at scheduled times.

Use PNG, JPEG, raw, PGM or PPM. A known filename extension selects the format; folders and stdout default to PNG.

-o - writes one image to stdout. Omit --json for binary output; this capture uses a temporary worker.

Schedules remain active while their GUI, headless session or direct process runs. They are not restored after exit.

Record and forward video

Record a bounded file or send video to another service.

A file recording defaults to a 512 MiB limit. Set enough space for the requested duration.

With --duration, the CLI waits and the camera worker stops the encoder at the deadline. Ctrl-C stops it early.

Without a duration, session recording returns immediately. Direct recording runs until Ctrl-C. Use status before retrying a timed-out request.

Sessions and shared activity

Open a workspace and control it from other processes.

gui and serve run in the foreground. Keep their process open while other CLI calls use the session.

Each camera has its own worker. Set --camera explicitly when multiple people or agents share a session.

Browser access has no separate login. Everyone who can reach the HTTP listener can control its session.

Saved setups

Save a tuned camera's settings by name and restore them later, with a preview of what changes.

A setup is kept on this computer in setups/ in the state directory. Restoring one is a single camera change that undo reverts, and a failed restore puts every value back. Setups never read or write the camera's own user sets.

Storage and retention

Set file retention limits and inspect storage usage.

The default policy allows 10 GiB and 10,000 owned files, then stops new output. Reservations count toward these limits.

Delete-oldest affects eligible Capturefab-owned files. Existing unrelated files and modified files are not deleted.

Storage task workspaces contain a database and its write-ahead log. Copy both together before removing an orphan workspace.

Camera sign-ins

Save user names and passwords for password-protected RTSP and ONVIF cameras.

Sign-ins are saved in the OS credential store under service capturefab-camera; camera-logins.json in the state directory lists addresses and user names only. The camera worker uses a saved sign-in for any credential-free camera with that address. A camera that asks for a sign-in fails with auth_required and one that refuses it with auth_rejected, both exit 1. Builds without the credential store refuse add and remove with exit 5.

RPC operations

Use structured JSON to control a running session.

Send a JSON object to capturefab --session NAME rpc through stdin. Set op to the operation below.

For HTTP, use POST /api/command with {version:1, camera:ID, command:{op:…}}.

Private local IPC uses an authentication token. The HTTP listener uses network access controls and has no separate login.

Use schema --json for runnable request examples, response fields and errors. Private IPC requests have a 1 MiB size limit.

printf '%s\n' '{"op":"frame","fresh":1,"max_dimension":1024}' | capturefab --session bench --camera sim:0 rpc --json

RPC frame format is auto, jpeg or png. Auto selects JPEG when supported, otherwise PNG.

RPC frame accepts fresh 0–10 and timeout_ms 1–10,000. The default timeout is 3,000 ms.

Its longest preview edge is 64–2,048 pixels, default 1,024. Use 0 for measurements only; encoded images have a 1.5 MiB limit.

Use normalized [x,y,width,height] for a region. A stopped camera acquires one frame and remains stopped; scanners are refused.
