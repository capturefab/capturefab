How to use commands

Run commands from a terminal or an agent.

Every command takes --json: stdout then holds exactly one JSON document, the result when the exit code is 0, or {"error":{code,message,hint,details}} otherwise. The exit code is the category: 0 ok, 1 failed, 2 usage, 3 unavailable, 4 timeout, 5 unsupported, 6 storage full, 130 interrupted. capturefab schema lists every command, its effect and every error code; capturefab schema COMMAND describes one.

Durations need a unit: 250ms, 2s, 1h30m. Feature names may address a bank, TriggerMode[FrameStart], and the controls exposure, gain, fps, roi, format, trigger, auto_exposure and auto_wb work on any camera that has them.

Capture, recording and sessions

Take frames and video, measure them, and keep cameras open between commands.

Capture and record block until they finish, in a worker of their own or in a session that holds the camera. --background leaves the work running in a session as a job instead, and --keep 5m runs a command through a session (named auto, started when none holds the camera) that stays open five minutes after its last use, so the next command starts at once. Ctrl-C ends a capture with exit 130 (143 for SIGTERM, 129 for SIGHUP) and the files saved so far in details.files; an open-ended recording ends normally.

Simulated cameras

Rehearse without hardware.

-c sim:0 opens a pattern camera with exposure, gain, a trigger selector bank and ExposureAuto. sim:line, sim:depth, sim:microscope and sim:thermal open other kinds, and sim:replay:PATH replays images or videos. capturefab list --kind sim lists it.

jobsRead capture jobs.

statusRead session and camera state.
