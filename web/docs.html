Capturefab documentation

Find cameras, save images and record video from the terminal. Start with the built-in simulator to learn the commands without a camera.

These guides describe the current source. Run capturefab --version to see your installed version. Use capturefab COMMAND --help or capturefab schema COMMAND for the options your version supports.

Your first capture

Use sim:0 to save your first image without connecting a camera.

  1. Install Capturefab.
  2. Open a terminal in a folder where you can save files.
  3. Run the commands below in order.
capturefab list --kind sim
capturefab info -c sim:0
capturefab capture -c sim:0 -o 'first-{seq}.png'
capturefab inspect -c sim:0

info shows the simulator's image size, pixel format and available controls. Open the file named in the capture result to see the test pattern. In an empty folder, this is first-0001.png. The {seq} template picks the next free number. inspect measures brightness and sharpness and prints the path to a JPEG preview.

To try a connected camera, run capturefab list. Replace sim:0 with the ID of your camera. If it does not appear, see Find cameras.

Use Capturefab from an AI agent

Coding agents such as Claude Code or Codex drive cameras through the CLI and read its JSON results.

  1. Put capturefab on the agent's PATH.
  2. Give the agent agents.md or ask it to run capturefab schema.
  3. Ask it to capture one image from sim:0 in the task folder.
  4. For real hardware, give it a camera ID and specify which settings it can change.
capturefab schema
capturefab schema capture
capturefab list --json
capturefab inspect --json -c sim:0 --preview none
capturefab capture --json -c sim:0 -o 'shots/{seq}.png'

Use --json for structured results and errors. Read the exit code and error.code before deciding what to do next. Use schema COMMAND to look up the options, result fields and errors for one command.

Command effects, from capturefab schema
EffectExamplesSuggested permission
readlist, info, features, get, inspect, jobs list, doctor, schemaAllow for the task
file_writecapture, record, preset saveAllow in the task's folder
camera_writeset, auto, preset apply, jobs stopAllow for the task's cameras
disruptiveexec, session start, session stop, serve, debug writeAsk first

Review flags as well as command names. --set, --auto and network --tune leave camera settings changed. inspect --preview PATH and debug xml -o FILE write to the specified paths.

If your agent tool uses prefix rules, allow specific subcommands such as capturefab jobs list. A rule for capturefab jobs also matches capturefab jobs stop all.

Use inspect --preview none for measurements alone. To give the agent a preview, use --preview PATH to save it in the task folder. Otherwise, capturefab doctor --json gives the default preview folder in inspect_dir.

Install and verify

One command picks the build for this computer, checks its SHA-256 and installs capturefab for your account.

# macOS and Linux: ~/.local/share/capturefab, with the command in ~/.local/bin
curl -fsSL https://capturefab.com/install.sh | sh
# Windows PowerShell: %LOCALAPPDATA%\Programs\Capturefab, on your user PATH
irm https://capturefab.com/install.ps1 | iex

The installers use your account's permissions. You can read the macOS and Linux script or the Windows script before running it. To see which file the installer would use, run the saved script with --dry-run on macOS or Linux, or -DryRun on Windows.

To download by hand, select a build for your operating system and processor. Use ARM64 for Apple silicon and x64 for Intel Macs. In the commands below, replace DOWNLOADED_FILE with the filename and EXPECTED_SHA256 with its checksum from the download page.

# Linux
echo "EXPECTED_SHA256  DOWNLOADED_FILE" | sha256sum -c
# macOS
echo "EXPECTED_SHA256  DOWNLOADED_FILE" | shasum -a 256 -c
# Windows PowerShell
if ((Get-FileHash .\DOWNLOADED_FILE -Algorithm SHA256).Hash -eq 'EXPECTED_SHA256') { 'OK: checksum matches' } else { 'MISMATCH: do not open this file' }

Run the command for your operating system from the folder with the download. If the checksum matches, extract the archive. It contains capturefab or capturefab.exe, a README and the license files.

Put capturefab on your PATH

The Windows installer updates your user PATH. The macOS and Linux installer prints instructions if its command folder is missing from PATH. If you downloaded and extracted the archive by hand, use the commands for your operating system below.

# macOS and Linux, from the extracted folder
install -Dm755 ./capturefab ~/.local/bin/capturefab   # Linux
mkdir -p ~/.local/bin && cp ./capturefab ~/.local/bin/  # macOS
# Windows PowerShell, from the extracted folder
$dir = "$env:LOCALAPPDATA\Programs\Capturefab"
New-Item -ItemType Directory -Force $dir | Out-Null; Copy-Item -Recurse -Force .\* $dir
$path = (Get-Item HKCU:\Environment).GetValue('Path', '', 'DoNotExpandEnvironmentNames')
New-ItemProperty HKCU:\Environment Path -PropertyType ExpandString -Value "$path;$dir" -Force | Out-Null

Open a new terminal and run capturefab --version. If it is not found on macOS or Linux, add export PATH="$HOME/.local/bin:$PATH" to ~/.zshrc or ~/.profile.

Upgrade or uninstall

Download the current installer again to upgrade. On macOS/Linux pass --upgrade or --uninstall; on Windows save install.ps1 and run it with -Upgrade or -Uninstall. Add --dry-run (-DryRun) to preview. Custom installs need the same --prefix and --bin-dir (-Prefix on Windows). Close running commands and sessions before uninstalling.

Uninstall removes recognized release folders and their command link or PATH entries. Presets, saved sign-ins, caches and files outside those release folders stay. See the copyable upgrade/uninstall commands and agent installation instructions. A saved installer can uninstall offline; download a fresh script to install the latest version.

First use: system prompts

The first camera or network command can make your system ask for permission. These answers decide whether cameras appear.

Prompts on first use
SystemWhat to expect
macOS

macOS asks for Camera and Local Network access for the app you run the command in, such as Terminal, iTerm or your editor. Allow both: webcams need Camera, and GigE Vision, ONVIF and RTSP discovery need Local Network. To change them later, open System Settings › Privacy & Security › Camera or Local Network and turn that app on. A download from a browser is checked online by Gatekeeper the first time it runs.

Windows

A build marked Unsigned on the download page can show Windows protected your PC from SmartScreen. Check the SHA-256 first, then choose More info → Run anyway, or run Unblock-File .\capturefab.exe. The PowerShell installer needs neither.

When Windows Defender Firewall asks, allow Capturefab on Private networks. GigE Vision and RTSP-over-UDP video arrive as inbound UDP; blocking it shows up as stream timeouts.

USB3 Vision needs WinUSB. The camera's USB3 Vision interface must use the WinUSB driver. Close vendor camera software first. Use the vendor's driver tool if it can switch the camera to WinUSB; otherwise run Zadig, choose Options › List All Devices, select the camera's interface, choose WinUSB and select Replace Driver. Vendor software that needs its own driver cannot open the camera until you roll the driver back in Device Manager.

Linux

There are no prompts, but USB3 Vision cameras need device permissions and GigE Vision needs a larger socket receive buffer. Run capturefab doctor: it checks both and prints the command for each fix. The line computer guide explains the udev rule and net.core.rmem_max.

Upgrade from the desktop app

Capturefab is now a command-line tool. Releases up to 0.5.0 were a desktop app with a CLI inside.

The desktop window, browser client, built-in AI assistant, datasets, camera hubs, document scanners, workflow files and update checks are gone. Cameras, captures, recordings and saved sign-ins work as before through the commands on this page, with new names and a new JSON contract: read the command reference before you reuse a script.

  • macOS: run the install script. It replaces a ~/.local/bin/capturefab link into Capturefab.app and says what it changed; the app itself stays until you delete it. If your shell profile adds /Applications/Capturefab.app/Contents/MacOS to PATH, remove that line.
  • Linux: the install script removes the launcher entry and icons an earlier install added. Earlier versions stay in ~/.local/share/capturefab until you delete them.
  • Windows: the install script removes the Start menu shortcut an earlier install added and keeps one Capturefab folder on your PATH.

Files the desktop app kept, such as its preferences, saved hubs, destinations and dataset files, are not read any more; delete them when you no longer need them. Saved camera sign-ins stay in the OS credential store and keep working. To keep using the desktop app, keep version 0.5.0 and skip the update it offers; its downloads remain at https://capturefab.com/download/v0.5.0/, with each file listed in releases.json.

Cameras

Find cameras

list searches for connected cameras and prints an ID you can pass to -c.

capturefab list
capturefab list --kind gige,u3v --timeout 3s
capturefab list --kind webcam
capturefab --json list

Use --kind to filter the search. Screen sources and simulators appear only when you ask for screen or sim. Use --timeout to give GigE Vision and ONVIF cameras more time to reply. If a search fails for one connection type, read warnings in the JSON result.

In scripts, pass the camera ID with -c. A unique serial number or a GigE camera’s IPv4 address also works. If you omit -c and Capturefab finds several cameras, it can prompt you to choose in a terminal. An ambiguous selector returns camera_ambiguous.

A GigE camera needs a reachable address on a wired adapter's subnet; capturefab network checks the path. USB3 Vision needs operating system access: the udev rule on Linux, an available IOKit interface on macOS and WinUSB on Windows. Read the camera requirements and limits.

Cameras

Simulated cameras

Built-in cameras for learning, scripting and tests without hardware.

sim:0 and other numbered simulators generate a moving pattern. They support exposure, gain, frame rate, region, several pixel formats and triggers. Use sim:line, sim:depth, sim:microscope or sim:thermal to try a different camera type. Use sim:replay:PATH to replay a video, an image or a folder of media files.

capturefab inspect -c sim:0 --set exposure=40ms
capturefab capture -c sim:0 -c sim:1 -o 'multi/{camera}-{seq}.png'
capturefab capture -c sim:replay:/data/clip.mp4 -n 100 -o replay-frames/

Simulator settings stay in the runtime folder between commands. Use capture --set to change settings before saving an image. See the simulator guide for replay and trigger options.

Cameras

Read and change settings

Use info to see what a camera supports. Use get and set to read and change its settings.

capturefab info -c sim:0
capturefab features -c sim:0 Trigger
capturefab features -c sim:0 'Exposure*' --all
capturefab get -c sim:0 exposure gain ExposureTime 'TriggerMode[FrameStart]'
capturefab set -c sim:0 exposure=5ms gain=3
capturefab set -c sim:0 roi=0,0,320,240 fps=20 --dry-run
capturefab exec -c sim:0 'TriggerSoftware[FrameStart]'

Use portable controls such as exposure, gain, fps and roi when the camera supports them. For a GenICam feature, use the name from features, such as ExposureTime. A selector in brackets, such as TriggerMode[FrameStart], chooses which value to read or change. Quote names with brackets so the shell passes them as written.

Use set --dry-run to see the planned writes in order. After a write, the result shows the value read back from the camera. A camera can round a value to its supported increment.

If a write fails, Capturefab tries to restore the earlier values. Read error.details.rollback to see which values it restored and which it could not restore.

For an unknown feature, look for details.did_you_mean. For an out-of-range value, look for details.nearest.

features shows common features by default. Use a name pattern, --category or --all to see more. exec runs a command feature such as UserSetSave[UserSet1].

Cameras

Measure exposure and focus

inspect measures a fresh frame and writes a small preview, without saving a capture.

capturefab inspect -c sim:0
capturefab inspect -c sim:0 --set exposure=20ms --region 0.25,0.25,0.5,0.5
capturefab inspect -c sim:0 --keep 5m --preview none
capturefab --json inspect -c sim:0 -v --preview none
capturefab watch -c sim:0 --show --for 5s
  • Read verdict for conditions such as dark or clipped_high. One frame can have more than one condition.
  • Read exposure for brightness and counts of pixels at black or full scale. When present, suggest gives an exposure to try.
  • Compare focus.sharpness across frames from the same camera and scene. Higher values indicate sharper edges. Use -v for a histogram and more focus measures.

Use --set to change settings before measuring. Use --region X,Y,W,H to measure part of the frame. Each number is a fraction of the full width or height. The JPEG preview’s longest edge is 768 pixels by default. Use --size to change it, or --preview none to skip the preview.

Use --for 10s --every 200ms to measure a series and get the sharpest frame’s results. For live measurements, use watch. Add --show to see frames in a compatible terminal, or --json for one JSON line per measurement.

Use --fresh N to skip extra frames before measuring. If verdict contains not_settled, the camera’s automatic exposure was still changing when --warmup ended.

Cameras

Auto exposure

auto settles exposure and gain, then holds them.

capturefab auto -c sim:0
capturefab auto -c sim:0 --timeout 10s
capturefab auto -c sim:0 --off
capturefab capture -c sim:0 --auto -o settled.png

auto uses the camera’s auto exposure when available. Capturefab adjusts exposure and gain itself if the camera has no auto mode or if you set --region or --max-exposure. Read settled even when the command exits 0. If present, limited_by names the limit that affected the result.

Use --off to turn off automatic exposure, gain and white balance while keeping their current values. Use --continuous to keep adjusting exposure. Capturefab’s own continuous loop runs only in a session. A camera without exposure control or one that waits for external triggers can return unsupported.

Cameras

Triggered capture

With a software trigger, capture fires it; with a hardware trigger, it waits for the line.

capturefab capture -c 'sim:0?line0=every:500ms' --set trigger=software -o 'software-{seq}.png'
capturefab set -c 'sim:0?line0=every:500ms' trigger=line0:rising --keep 5m
capturefab capture -c 'sim:0?line0=every:500ms' -o 'part-{seq}.png' --timeout 30s
capturefab set -c 'sim:0?line0=every:500ms' trigger=off

sim:0?line0=every:500ms supplies a Line0 trigger every 500 ms. Plain sim:0 does not supply those signals. The trigger setting stays in effect for later commands. Set trigger=off to return to free-running capture.

For a hardware trigger, capture waits up to --timeout per frame. The default wait is at least 5s. If no trigger arrives in time, it exits 4 with trigger_timeout. For a long wait, use --timeout none --background and follow the job ID with jobs.

Capture & record

Capture images

capture saves one frame, a burst, a time lapse or a delayed capture, and never overwrites a file.

capturefab capture -c sim:0 -o shot.png
capturefab capture -c sim:0 -n 10 -o frames/
capturefab capture -c sim:0 -o shot.jpg --quality 85
capturefab capture -c sim:0 -o frames/ -f raw
capturefab capture -c sim:0 --set exposure=20ms --set gain=6 -o bright.png
capturefab capture -c sim:0 -o shot2.png --dry-run
Image formats
FormatUse
pngThe default. Saves high-bit-depth monochrome frames as 16-bit grayscale. Saves color and Bayer frames as 8-bit RGB.
jpgUse --quality from 1 to 100. The default is 90 for encoded JPEGs. For Motion JPEG input, Capturefab can save the source JPEG directly. Look for "passthrough": true. To encode it again, set --quality.
rawSaves the frame buffer at its original bit depth. For FFmpeg sources, this is the decoded frame. A file such as shot.raw.json describes the pixel format, dimensions and layout of shot.raw.

See the pixel format table for supported conversions. The result gives the output bit_depth. If the file uses fewer bits than the input, it also gives source_bits.

The output extension sets the format. Use -f to choose a format when there is no extension. End a new folder path with / to save numbered files there. If you omit -o, Capturefab saves to the current folder.

Use -o - to write one image to stdout. With --json, the result or error goes to stderr in this mode.

Use --timeout to set the wait per frame. The default is at least 5s and can be longer for slow cameras. Use --set or --auto to adjust the camera before capture.

A fixed filename that already exists returns exists unless you pass --on-exists number. Use {seq} to choose the next free number automatically.

Repeat -c to request frames from several cameras together. A foreground result has one entry per camera in cameras. skew_ms measures how far apart the first frames arrived. For synchronized exposures, use a shared hardware trigger. With --background, the result has a jobs list instead.

capturefab capture -c sim:0 -o measured.png --inspect --manifest shots.jsonl
capturefab capture -c sim:0 --set exposure=20ms --fresh 2 -o after.png
capturefab capture -c sim:0 -n 100 -o 'scratch/{seq}.raw' --sync none

Use time for the frame’s host timestamp and device_ts_ns for the camera’s own clock when available. For a burst, read fps, gaps and consecutive to see how the capture ran.

Use --fresh N to skip extra frames after a change. Use --inspect to measure the last frame. Use --manifest FILE to append a JSON line for each saved file with its path, SHA-256, settings and tags. The default sync writes each capture to disk before reporting it. Use --sync none for temporary images you can afford to lose after a power failure.

Capture & record

Name files and tag captures

Templates in -o build file names from the camera, time, sequence and your tags.

capturefab capture -c sim:0 -n 10 -o 'parts/{date}/{tag:part}-{seq:4}.png' --tag part=A-100 --tag station=3
capturefab capture -c sim:0 -o 'labels/{tag:label}/{seq:5}.png' --tag label=defect
capturefab capture -c sim:0 -o shot.png --on-exists number
Output placeholders
PlaceholderValue
{camera}The camera's model and serial, safe for file names
{serial}The serial number
{seq}, {seq:N}1, 2, 3 …, padded to N digits (4 by default)
{frame}Frame number within this capture, starting at 000001
{time}The time, such as 20261031-142233.123
{date}The date, such as 2026-10-31
{datetime}Date and time to the second, such as 20261031-142233
{tag:KEY}The value of --tag KEY=VALUE
{ext}png, jpg or raw

Capturefab saves tags and camera settings in PNG and JPEG metadata. Relative paths start in the folder where you run the command, even when a session writes the files. Use --on-exists number to add -0001, -0002 and so on when a fixed name is already in use. See the plant-floor guide for naming and tagging examples.

Capture & record

Time lapses and delayed captures

--every spaces frames, --for or -n bounds them, and --at or --in delays the start.

capturefab capture -c sim:0 -n 3 --every 2s -o 'lapse/{seq:5}.png'
capturefab capture -c sim:0 --in 5s -o 'later-{seq}.png'
# Schedule a capture for 06:00 local time
capturefab capture -c sim:0 --at 06:00 -o 'morning-{seq}.png' --background

Give durations a unit, such as 250ms, 2s or 1h30m. Use --at HH:MM for a time on the local clock, or pass an RFC 3339 timestamp with its time zone.

Use --background to return a job ID while a session runs the capture. In JSON, read job.id. Pass that ID to jobs wait or jobs stop. See sessions and jobs.

Capture & record

Record and stream video

record writes video to a file or streams it to a server through the bundled FFmpeg.

capturefab record -c sim:0 -o 'clip-{seq}.mp4' --for 5s
capturefab record -c sim:0 -o 'lossless-{seq}.mkv' --codec ffv1 --for 5s
capturefab record -c sim:0 -o 'limited-{seq}.mp4' --bitrate 4M --max-size 2G --for 5s

To stream video, start a receiver such as MediaMTX first. Use the URL for the protocol your receiver accepts.

capturefab record -c sim:0 -o rtsp://localhost:8554/cam --for 10s
capturefab record -c sim:0 -o 'srt://localhost:8890?streamid=publish:cam' --for 10s

For a local file, use .mkv, .mp4, .mov, .ts or .webm. Choose a container that supports the codec.

Use --codec ffv1 in an MKV file for lossless video. For Bayer input, it saves the mosaic as gray samples. When Capturefab encodes H.264, it tries hardware first and can use libx264 from the bundled FFmpeg. HEVC and AV1 encoding need a supported hardware encoder.

On supported systems, Capturefab can copy H.264 or HEVC video directly into the output. Look for "encoder":"copy". A recording can start at the previous key frame. To encode instead, set --fps, --bitrate or a different codec. Windows always encodes.

Use --for or --max-size to limit a recording. To stop a foreground recording, push Ctrl-C. Read ended and finalized in the JSON result to see how it ended and whether Capturefab finished writing the file.

LMI GoPxL sensor measurements are polled over Ethernet ASCII with declared framing, keeping native values and decision bits; see the GoPxL guide.

Opto 22 groov EPIC and RIO inputs are read over OptoMMP with an explicit model and exact expected module and channel-type IDs, preserving native values and quality codes. Clear Powerup Clear and coordinate the watchdog externally; see the OptoMMP guide.

Atlas Copco PF6000 tightening-result subscriptions preserve native values and raw frames with a JSONL checkpoint before acknowledgment. Configure the Virtual Station and Disconnect=None externally; see the PF6000 guide.

Record industrial data

Record signals from multiple industrial sources on a shared host timeline, then export CSV or JSON Lines.

The ni-daqmx feature, included by default, captures continuous internal-clock or explicit software on-demand voltage, thermocouple, current, RTD, strain, bridge ratio or acceleration input through an installed NI driver on supported Linux/Windows hosts. It uses an isolated worker, explicit physical AI channels and bounded scan-major blocks with exact scaled F64 words and native statuses. Thermocouple channels declare units and built-in or constant CJC; current channels declare ampere ranges, terminals and built-in or external shunts. Temperature and current values retain their driver units without local conversion or V/R arithmetic. RTD channels explicitly declare type, temperature units, wiring, sensor R0 and excitation current. Internal excitation can energize the sensor; external excitation is operator supplied. Configured settings are not physical readbacks or blanket module qualification. Explicit measurement:"mixed" combines tagged per-channel measurements, including different ranges or terminals within one family, in one task while preserving old configs and rows. One ordered descriptor vector binds zero-based channel index, actual physical channel, measurement, quantity, units and requested settings to each sample column; raw F64 and finite family values need no global unit or repeated sample tags. Repeats remain, with no per-channel timestamps or simultaneous/fresh-conversion claim. Explicit software-only digital_port captures complete unsigned port words with assigned read names and queried line counts separate from physical requests. counter_count preserves U32 snapshots without unwrapping or hardware-width inference; counter_frequency retains raw F64 and finite Hz without deriving a rate from host time/counts. Counter modes use exactly one typed channel, explicit fields and an optional non-null input-terminal request. Input resource configuration and paired-counter methods are not passive monitoring or hardware qualification. On-demand requires an explicit poll_interval_ms, omits hardware-rate and buffer settings, and requests one scan per read. Host pacing does not establish a fresh device conversion or real-time schedule. See NI input configuration for limits, unqueried defaults and clock semantics.

New strain, bridge_ratio and acceleration profiles also work in MixedAI. Strain retains seven bridge layouts and explicit sensor constants; ratio keeps V/V or mV/V; acceleration keeps g, m/s² or in/s² with separate sensitivity units. Internal/external/none excitation always has an explicit voltage or current request, and optional AC/DC/ground coupling remains unqueried when omitted. Ground measures ground; none and Stop/Clear do not promise physical power-off. Exact raw F64 and finite strain/ratio/acceleration values undergo no local scaling. Software-only counter_period, counter_pulse_width, counter_angular_position and counter_linear_position use one typed counter and preserve native seconds or position. Encoder PPR/distance, initial value and all Z-index fields are explicit; enabled Z can reset the measurement, with phase ignored in two-pulse mode. Routes, electrical limits, persistent/coerced excitation and actual module/chassis/driver/OS support require separate qualification.

Additional resistance, thermistor_current, thermistor_voltage, force_bridge, pressure_bridge and torque_bridge AI profiles also work in MixedAI, with the same per-channel request contract. Resistance retains native ohms. Thermistors require explicit coefficients for NI's Kelvin/ln(R) model; voltage excitation additionally requires positive reference R1 ohms, not RTD R0. Physical bridges keep returned units, electrical calibration units and physical calibration units separate, preserving declared point order. Equal electrical coordinates are rejected; descending and equal-physical requests retain native rejection without a universal acceptance promise. Calibration provenance describes the requested mapping, not a performed sensor calibration. Exact F64 and finite family values receive no local equation, interpolation or unit conversion. Excitation and optional AC/DC/ground coupling remain requests; none and Stop/Clear do not promise power-off or physical qualification. See the NI input guide for all required channel fields and limits.

Additional velocity_iepe, force_iepe, charge_acceleration, lvdt and rvdt measurements support both AI timing modes and MixedAI, now with eighteen channel kinds. Output units and sensitivity units are separate explicit requests: velocity m/s can use mV/(mm/s), charge acceleration uses pC sensitivity, LVDT includes mV/V per milli-inch, and RVDT uses angular sensitivity. The first three require terminal configuration; LVDT/RVDT instead require explicit AC excitation frequency and four/five/six-wire mode. All five preserve driver F64 words and finite velocity/force/acceleration/position/angle without local conversion. Sensitivity accepts finite signed and zero requests with native rejection preserved; older acceleration keeps its positive-only rule. Excitation and optional coupling remain requests, with no inferred calibration, delivered power or physical device qualification.

Installed vendor GenTL/CTI producers can be selected with list --kind gentl after configuring CAPTUREFAB_GENTL_PRODUCERS or GENICAM_GENTL64_PATH. See the camera guide for driver setup and payload limits. GenTL multipart local stills retain every component; ambiguous image selections return copyable camera IDs, and capture results reference each component archive. The archive JSON lists selectors for Coord3D_C16 and Confidence16 maps that can be saved as RAW or 16-bit PNG, and Coord3D_ABC32f point clouds that can be saved as RAW. Native GigE multipart local stills retain all synchronized components in the documented unchunked stream layout. Select an interleaved XYZ part for RAW output with capture --part-format Coord3D_ABC32f or the industrial camera source's part_format. GenTL 1.6 stills can archive a supported complete GenDC container and save selected image samples without row or part padding. Ordinary native GigE Coord3D_ABC32f point clouds and Coord3D_AC16 profiles save as RAW with interleaved sample layouts in their sidecars. Native GigE/USB and GenTL chunk artifacts retain original bytes plus XML-derived values and units. Saved metadata and frame indexes preserve raw device-clock ticks and optional frequency separately from nanoseconds.

Run capturefab data protocols --json for adapter requirements and a runnable simulator configuration in example. Save that object as sources.json.

capturefab data record --config sources.json --for 30s -o run.jsonl
capturefab data export run.jsonl -o run.csv
capturefab data export run.jsonl -o press.jsonl --format jsonl --source press

Native adapters capture camera stills, Keyence KV Host Link, Modbus TCP with gateway unit selection and optional TLS, serial Modbus RTU and ASCII on Unix terminals or Windows COM ports, classic S7 absolute reads, SLC/MicroLogix PCCC file reads over EtherNet/IP or serial DF1, SLC 5/05 file reads over legacy CSPv4, PLC-5/E file reads over EtherNet/IP, Beckhoff ADS, Mitsubishi SLMP 3E binary or ASCII, MC 1E and serial FX Computer Link, Panasonic FP MEWTOCOL-COM, and Omron FINS TCP/UDP, serial Host Link and CompoWay/F reads, BACnet/IP meter and controller values, IEC 62056-21 and passive SML optical meter readouts, shared-bus SDI-12 environmental sensors through a USB serial bridge, Vaisala WXT530 serial weather measurements, SICK TiM single-scan LiDAR, passive Gocator GDP profile archives, TCP and serial JSONL sensor streams, plus SCPI instrument queries over raw TCP, native serial, VXI-11, HiSLIP or USBTMC (usb feature), METTLER TOLEDO MT-SICS weights over TCP or serial, MQTT 3.1.1 (QoS 0–2) over TCP or verified TLS with optional credentials and client certificates, EtherNet/IP reads of Logix, Micro800 and Omron NJ/NX variables and CIP Assembly data, plus ifm IO-Link process input or the standard IO-Link JSON GET interface. Keyence IV inspection results and Cognex In-Sight cells can share a recording. Linux can passively capture EtherCAT, Profinet RT, CAN and CAN FD with a configured IO layout and raw-packet permission. Passive SICK multiScan100/picoScan100 Compact UDP capture retains scan/IMU datagrams and native words in local archives. Explicit picoScan150 profiles also retain encoder ticks and mixed scan/IMU/encoder datagrams without inferring physical units. Compact TCP capture preserves whole LRS4000 scan telegrams and multiScan200 scan, ambient-light and IMU telegrams, with bounded native parts. OPC-UA Read services and explicit queued subscriptions are built into the CLI, with anonymous or pinned SignAndEncrypt sessions and no separately installed SDK runtime. Subscription envelopes retain native quality, clocks and sequence metadata, with bounded Republish recovery; acknowledgements confirm local receipt, with a crash gap before JSONL persistence. Custom Unix or Windows 10/Server 2016+ absolute .exe helper sources accept vendor SDK and protocol bridges, with existing protocol-specific overrides also available. See the industrial data guide for configuration and the helper contract.

Samples keep elapsed host monotonic time, UTC receive time, read duration and available device time. This supports host correlation; it does not synchronize device clocks. Camera still sources share the sensor timeline using frame-receive timestamps, with encoding/storage delay reported separately as delivery_latency_ns. Add a video source for a local clip and per-frame index, optionally sharing the same camera with still captures. Presentation frame numbers map to host receive times, and finalization drains pending video metadata before the run is complete. Source failures stop acquisition and keep complete samples, with saved-work details in the command error. Use --allow-incomplete explicitly to export a failed or interrupted run.

Capture & record

Save and restore settings

A preset keeps a camera's settings on this computer and restores them as one change.

capturefab preset save bench -c sim:0 --note 'ring light 60%'
capturefab preset list
capturefab preset apply bench -c sim:0 --dry-run
capturefab preset apply bench -c sim:0
capturefab preset export bench -o bench.json
capturefab preset import bench.json --name bench2

Use apply --dry-run to review changes before applying them. The plan marks disruptive changes such as triggering or I/O settings. Use --strict to stop if a saved value does not fit the camera. Use --allow-other-model to apply compatible settings to another model.

If a write fails, Capturefab tries to restore the earlier settings. To save the applied settings as the camera’s power-on defaults, use --persist on cameras that support user sets.

Capture & record

Password-protected cameras

login add saves a stream's user name and password in the OS credential store.

printf '%s\n' "$PASSWORD" | capturefab login add rtsp://cam.local/stream --user admin --password-stdin
capturefab login list
capturefab onvif resolve cam.local
capturefab login rm rtsp://cam.local/stream

Use a camera address without credentials. Supply the password on stdin with --password-stdin, or set CAPTUREFAB_CAMERA_PASSWORD. In this example, PASSWORD is a shell variable you set before running the command.

By default, login add verifies the sign-in before saving it. Use --no-check to skip the connection. Later commands for that address use the saved credentials. If credentials are missing or the camera rejects them, look for auth_required or auth_rejected.

Capturefab passes RTSP credentials to FFmpeg in its input URL. On systems where other users can read process arguments, they can see those credentials. RTSP Basic authentication also exposes credentials on an unencrypted connection. Use rtsps:// if the camera supports it.

Automate

Sessions, --keep and jobs

A session keeps cameras open between commands and runs background jobs.

Run a capture in a named session

capturefab session start --name bench -c sim:1 --live
capturefab capture --session bench -c sim:1 -n 3 --every 2s -o 'bench/{seq}.png' --background
capturefab session status bench

Replace JOB_ID below with the ID from the capture result.

capturefab jobs wait JOB_ID --timeout 10s
capturefab session stop bench

Capturefab normally holds a camera in the auto session for 60 seconds after a command. Use --keep DUR to change that time. Use --keep 0 to avoid starting a warm session. Use --no-session to bypass existing sessions as well.

session start runs a named session in the background with a default idle limit of 30 minutes. Use --session NAME to select it. --live keeps frames flowing between commands. For a service manager, use serve --name NAME to run the session in the foreground. See the line computer guide.

Use jobs list --running to see active jobs. jobs wait exits 0 when all requested jobs succeed. It returns a failed job’s exit code, or exits 4 if the wait times out. Use jobs stop JOB_ID to stop a specific job and keep the files it saved. Stopping a session interrupts its active jobs.

See CLI workflows for examples of how to combine these commands in scripts.

GigE network checks

To receive a GigE multicast stream managed by another controller, use the quoted gige-monitor://CAMERA_IP?interface=HOST_IP&mac=12_HEX_DIGITS selector. It reads the existing stream configuration and receives images without changing camera settings or acquisition. See monitor requirements for interface, source-port and control limits.

network checks how each GigE camera is reached; --tune shares bandwidth between cameras.

capturefab network
capturefab network --tune -c gige:00c0df123456 -c gige:00c0df654321

Run network to see which adapter reaches each GigE camera. It reports the adapter’s IPv4 address, MTU and link speed when available. Use --tune to set camera packet delays or throughput limits when cameras share a link. Tuning changes camera settings only.

Troubleshooting

Read error.code and error.hint first; doctor checks the computer.

capturefab doctor
capturefab --json list
capturefab session list
capturefab -v info -c sim:0
A camera is missing or cannot connect

Read the warnings of list and use the camera's full ID. For GigE, network checks reachability on its subnet. For USB3 Vision, check operating system access: doctor prints the Linux udev rule, and on Windows the camera must use WinUSB. On macOS, a camera at a correct address that reports no route to host can mean Local Network access was denied to your terminal app.

camera_busy: another process holds the camera

A session or another command has the camera open; error.details.held_by names it when known. Run the command through that session (--session NAME), wait for its job, or stop it with jobs stop or session stop.

frame_timeout or trigger_timeout

Make sure the camera streams and that its trigger can supply frames: info shows the trigger. Raise --timeout for slow sources, or set trigger=off. For GigE, packet loss looks like timeouts: check the receive buffer and network.

A setting is locked or rejected

feature_locked names the setting that locks it in details.locked_by; change that first. Some features can change only while the camera is not streaming. set --dry-run shows what a change would write.

A frame's pixel format is unsupported

Choose another PixelFormat the camera offers, or capture raw to keep the bytes as they are. The pixel format table lists the supported formats.

A stream, video file or encoder fails

doctor shows whether FFmpeg runs. Make sure a receiving server is up and reachable. hevc and av1 need a working hardware encoder; h264 always has libx264. A development build can use CAPTUREFAB_FFMPEG=/absolute/path/to/ffmpeg.

An SSH shell cannot find a session a service started

Without XDG_RUNTIME_DIR, a Linux service uses /run/user/<uid> only when its user lingers. Run sudo loginctl enable-linger USER and give the service Wants= and After=user@<uid>.service. doctor in the SSH shell says where a service keeps its sessions.

Capture stops with storage_full

A write would have taken the disk below the free space Capturefab leaves for the system: 1% of the disk, at least 512 MiB and at most 20 GiB. error.details gives the path and its free_bytes. Free space or capture to another disk; CAPTUREFAB_MIN_FREE (bytes or a size such as 2G, 0 for none) changes the floor. Capturefab never deletes files to make room.

For a bug report, include capturefab --version, the operating system, the camera type, the exact command and its JSON output, and capturefab --json doctor. Remove private addresses and names before you share them.

Build, architecture and licensing

Capturefab runs each camera in its own worker process. It runs FFmpeg as a separate executable.

Capturefab implements GigE Vision, USB3 Vision and GenICam in Rust. The camera worker belongs to the command or to a session. This separation helps other camera workers continue when one fails. Capturefab uses FFmpeg for webcams, streams, media files and video encoding.

Build from source

Install a stable Rust toolchain, a C compiler and CMake. On x86, also install NASM for libjpeg-turbo. Download the release source archive. Replace VERSION below with the version you downloaded.

tar -xzf capturefab-VERSION-source.tar.gz
cd capturefab-VERSION
cargo --config .cargo/vendor-config.toml build --release --offline --locked
target/release/capturefab capture -c sim:0 -o first.png

To bundle FFmpeg, build it separately and set CAPTUREFAB_FFMPEG_BINARY when building Capturefab. At run time Capturefab looks for CAPTUREFAB_FFMPEG, the bundled copy, a copy next to capturefab, then a copy on PATH. See the FFmpeg build guide.

The default features are usb (USB3 Vision), gentl (an isolated consumer for installed CTI camera drivers), ni-daqmx (isolated NI input through a separately installed driver on supported Linux/Windows hosts), jpeg (libjpeg-turbo), videotoolbox (Apple's JPEG engine on macOS), nvjpeg and vaapi (the GPU JPEG encoders on Linux, whose libraries are loaded at run time in a helper process, so a build needs no SDK), keychain (the OS credential store for login), shell (line editing in capturefab shell) and mqtt-tls (verified MQTT TLS); --no-default-features builds without them, and doctor --json lists what a build has.

Licensing and release provenance

Capturefab uses the MIT license. The embedded FFmpeg is GPLv3 with x264, SRT, OpenSSL and zlib; capturefab licenses prints both notices. See the FFmpeg build and compliance guide. The downloads page shows how to verify each file, and the release manifest lists files, checksums and build metadata.
