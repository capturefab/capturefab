Documentation

Find cameras. Capture images. Script it.

One capturefab command for people, scripts and AI agents. Learn with the simulator camera, then connect your own.

These guides describe the current source. An installed release can differ: capturefab --version names it, and capturefab COMMAND --help and capturefab schema COMMAND list exactly what it accepts.

Start here

Your first capture

The simulator camera sim:0 lets you try every command without hardware.

  1. Install Capturefab.
  2. Open a terminal and run the commands below one at a time.
  3. Then replace sim:0 with an ID from capturefab list.
capturefab list --kind sim
capturefab info -c sim:0
capturefab capture -c sim:0 -o 'first-{seq}.png'
capturefab inspect -c sim:0
capturefab set -c sim:0 exposure=5ms gain=3
capturefab record -c sim:0 -o clip.mp4 --for 10s

info shows the image size, pixel format, exposure, gain, trigger and the controls the camera has. capture saves first-0001.png; run it again for first-0002.png, because Capturefab never overwrites a file. inspect measures brightness, clipping and sharpness and writes a small preview image. set changes several values as one change. record saves ten seconds of H.264 video.

Add --json to any command for one JSON document on stdout. Each command lists its options and examples with --help.

Use Capturefab from an AI agent

Coding agents such as Claude Code or Codex drive cameras through the CLI and read its JSON results.

  1. Install Capturefab where the agent runs, so capturefab is on its PATH.
  2. Give the agent agents.md, or tell it to run capturefab schema first.
  3. Allow the commands it may run without asking, by prefix (see below).
  4. Start with a bounded task on sim:0, then name the real camera.
capturefab schema
capturefab schema capture
capturefab list --json
capturefab inspect --json -c sim:0 --preview none
capturefab capture --json -c sim:0 -o 'shots/{seq}.png'

Every command takes --json and prints exactly one JSON document. The exit code gives the category and error.code the reason, so an agent knows what to do next without reading prose. schema describes every command in about 8 KB (roughly 2,500 tokens). Flags can follow the command, so a harness can allow commands by their first words.

Command effects, from capturefab schema
EffectExamplesSuggested permission
readlist, info, features, get, inspect, jobs, doctor, schemaAllow
file_writecapture, record, preset saveAllow in the task's folder
camera_writeset, auto, preset apply, jobs stopAllow for the task's cameras
disruptiveexec, session start, session stop, serve, debug writeAsk first

The effect is for a command without these flags: --set on inspect, capture and record, and --auto on capture and record, change camera settings and leave them changed, and network --tune writes camera network settings; inspect --preview PATH and debug xml -o FILE write that file, as a file_write command does. A prefix also matches every subcommand: a rule for capturefab jobs allows capturefab jobs stop all. Allow exact prefixes such as capturefab jobs list and capturefab jobs wait, and have the agent ask before a call with --set, --auto or --tune on a camera the task does not own.

inspect writes its preview into a private folder: capturefab --json doctor names it in inspect_dir. Let the agent read files there, or pass --preview none or --preview PATH. Your harness decides whether the model sees images. --keep 5m keeps a camera open between calls, which makes measuring loops fast.

Install and verify

One command picks the build for this computer, checks its SHA-256 and installs capturefab for your account.

# macOS and Linux: ~/.local/share/capturefab, with the command in ~/.local/bin
curl -fsSL https://capturefab.com/install.sh | sh
# Windows PowerShell: %LOCALAPPDATA%\Programs\Capturefab, on your user PATH
irm https://capturefab.com/install.ps1 | iex

The installers never use sudo or administrator rights. To read the script first: curl -fsSLO https://capturefab.com/install.sh; less install.sh; sh install.sh. --dry-run prints the file, URL and checksum it would use; --prefix DIR and --bin-dir DIR choose other folders.

To download by hand, open the download page. Select the build for your installed operating system and processor: Apple silicon uses ARM64, Intel and AMD PCs usually use x64. Check the file in the download's folder:

# Linux
echo "EXPECTED_SHA256  DOWNLOADED_FILE" | sha256sum -c
# macOS
echo "EXPECTED_SHA256  DOWNLOADED_FILE" | shasum -a 256 -c
# Windows PowerShell
if ((Get-FileHash .\DOWNLOADED_FILE -Algorithm SHA256).Hash -eq 'EXPECTED_SHA256') { 'OK: checksum matches' } else { 'MISMATCH: do not open this file' }

Linux and macOS print OK for a match; anything else means do not use the file. Then extract the archive. It holds the capturefab executable (capturefab.exe on Windows), a README and the license files.

Put capturefab on your PATH

The installers already do this. After a manual download, put the executable in a folder on your PATH:

# macOS and Linux, from the extracted folder
install -Dm755 ./capturefab ~/.local/bin/capturefab   # Linux
mkdir -p ~/.local/bin && cp ./capturefab ~/.local/bin/  # macOS
# Windows PowerShell, from the extracted folder
$dir = "$env:LOCALAPPDATA\Programs\Capturefab"
New-Item -ItemType Directory -Force $dir | Out-Null; Copy-Item -Recurse -Force .\* $dir
$path = (Get-Item HKCU:\Environment).GetValue('Path', '', 'DoNotExpandEnvironmentNames')
New-ItemProperty HKCU:\Environment Path -PropertyType ExpandString -Value "$path;$dir" -Force | Out-Null

Open a new terminal and run capturefab --version. If it is not found on macOS or Linux, add export PATH="$HOME/.local/bin:$PATH" to ~/.zshrc or ~/.profile.

Upgrade or uninstall

Download the current installer again to upgrade. On macOS/Linux pass --upgrade or --uninstall; on Windows save install.ps1 and run it with -Upgrade or -Uninstall. Add --dry-run (-DryRun) to preview. Custom installs need the same --prefix and --bin-dir (-Prefix on Windows). Close running commands and sessions before uninstalling.

Uninstall removes recognized release folders and their command link or PATH entries. Presets, saved sign-ins, caches and files outside those release folders stay. See the copyable upgrade/uninstall commands and agent installation instructions. A saved installer can uninstall offline; download a fresh script to install the latest version.

First use: system prompts

The first camera or network command can make your system ask for permission. These answers decide whether cameras appear.

Prompts on first use
SystemWhat to expect
macOS

macOS asks for Camera and Local Network access for the app you run the command in, such as Terminal, iTerm or your editor. Allow both: webcams need Camera, and GigE Vision, ONVIF and RTSP discovery need Local Network. To change them later, open System Settings › Privacy & Security › Camera or Local Network and turn that app on. A download from a browser is checked online by Gatekeeper the first time it runs.

Windows

A build marked Unsigned on the download page can show Windows protected your PC from SmartScreen. Check the SHA-256 first, then choose More info → Run anyway, or run Unblock-File .\capturefab.exe. The PowerShell installer needs neither.

When Windows Defender Firewall asks, allow Capturefab on Private networks. GigE Vision and RTSP-over-UDP video arrive as inbound UDP; blocking it shows up as stream timeouts.

USB3 Vision needs WinUSB. The camera's USB3 Vision interface must use the WinUSB driver. Close vendor camera software first. Use the vendor's driver tool if it can switch the camera to WinUSB; otherwise run Zadig, choose Options › List All Devices, select the camera's interface, choose WinUSB and select Replace Driver. Vendor software that needs its own driver cannot open the camera until you roll the driver back in Device Manager.

Linux

There are no prompts, but USB3 Vision cameras need device permissions and GigE Vision needs a larger socket receive buffer. Run capturefab doctor: it checks both and prints the command for each fix. The line computer guide explains the udev rule and net.core.rmem_max.

Upgrade from the desktop app

Capturefab is now a command-line tool. Releases up to 0.5.0 were a desktop app with a CLI inside.

The desktop window, browser client, built-in AI assistant, datasets, camera hubs, document scanners, workflow files and update checks are gone. Cameras, captures, recordings and saved sign-ins work as before through the commands on this page, with new names and a new JSON contract: read the command reference before you reuse a script.

  • macOS: run the install script. It replaces a ~/.local/bin/capturefab link into Capturefab.app and says what it changed; the app itself stays until you delete it. If your shell profile adds /Applications/Capturefab.app/Contents/MacOS to PATH, remove that line.
  • Linux: the install script removes the launcher entry and icons an earlier install added. Earlier versions stay in ~/.local/share/capturefab until you delete them.
  • Windows: the install script removes the Start menu shortcut an earlier install added and keeps one Capturefab folder on your PATH.

Files the desktop app kept, such as its preferences, saved hubs, destinations and dataset files, are not read any more; delete them when you no longer need them. Saved camera sign-ins stay in the OS credential store and keep working. To keep using the desktop app, keep version 0.5.0 and skip the update it offers; its downloads remain at https://capturefab.com/download/v0.5.0/, with each file listed in releases.json.

Cameras

Find cameras

list searches every transport at once and prints an ID for each camera.

capturefab list
capturefab list --kind gige,u3v --timeout 3s
capturefab list --kind webcam
capturefab --json list

Kinds are gige, u3v, webcam, onvif, screen and sim. Screen captures and simulators appear only when --kind names them. --timeout sets how long GigE and ONVIF broadcasts collect answers (default 1s). A transport that cannot be searched adds a line to warnings instead of failing the command.

Pass an ID to -c. A unique serial number or a GigE IPv4 address also works. Without -c, a command uses the only camera a session holds, or else the only camera list finds; with several it exits 2 with camera_ambiguous and lists the candidates, except at a terminal without --json, where it shows a numbered list and asks which (Enter takes the first). CAPTUREFAB_CAMERA sets a default.

A GigE camera needs a reachable address on a wired adapter's subnet; capturefab network checks the path. USB3 Vision needs operating system access: the udev rule on Linux, an available IOKit interface on macOS and WinUSB on Windows. Read the camera requirements and limits.

Cameras

Simulated cameras

Built-in cameras for learning, scripting and tests without hardware.

sim:0 (and sim:1, sim:2, …) is a moving pattern camera with exposure, gain, frame rate, region, pixel formats (Mono8, Mono12, Mono12p, Mono14p, Mono16, RGB8, RGB12, BayerRG8, BayerRG12, BayerRG12p), auto exposure and a trigger bank. sim:line, sim:depth, sim:microscope and sim:thermal act like those kinds of camera. sim:replay:PATH replays a video, an image or a folder of them.

capturefab inspect -c sim:0 --set exposure=40ms
capturefab capture -c sim:0 -c sim:1 -o 'multi/{camera}-{seq}.png'
capturefab capture -c sim:replay:/data/clip.mp4 -n 100 -o replay-frames/

A simulator keeps the settings you give it until its runtime folder is cleared, as a real camera keeps its own until it powers off, and commands keep it open for 60 seconds between them. capture --set changes settings and captures in one call. Read the simulated camera guide for replay rules.

Cameras

Read and change settings

info summarizes a camera; get and set read and write features and controls in one call.

capturefab info -c sim:0
capturefab features -c sim:0 Trigger
capturefab features -c sim:0 'Exposure*' --all
capturefab get -c sim:0 exposure gain ExposureTime 'TriggerMode[FrameStart]'
capturefab set -c sim:0 exposure=5ms gain=3
capturefab set -c sim:0 roi=0,0,320,240 fps=20 --dry-run
capturefab exec -c sim:0 'TriggerSoftware[FrameStart]'

Names are the camera's GenICam features (ExposureTime), a feature at a selector value (TriggerMode[FrameStart], or Feature[Selector=Value]; quote these in the shell, because zsh expands brackets), or a portable control: exposure, gain, fps, roi (x,y,w,h or full), format, trigger (off, software, line0:rising …), auto_exposure and auto_wb. Time features take durations: ExposureTime=10ms.

set writes every value as one change, in an order that keeps the camera valid: a size before its offset (the offset first when it gets smaller), an auto mode off before its value, a lower frame rate before a longer exposure. If a write fails, every value written is put back, and so is the rest of the image geometry a write moved (a binning rescales the size and offsets); the error's details.rollback lists what was restored. --dry-run checks the values against the camera and shows the writes in order. The result lists each changed value as read back, which can be rounded to the camera's increment.

A wrong name exits 2 with feature_not_found and close names in details.did_you_mean; a value outside the range exits 2 with out_of_range and details.nearest. features shows the common features by default; a pattern, --category or --all searches every level. exec runs a command feature, such as UserSetSave[UserSet1] to keep settings in the camera.

Cameras

Measure exposure and focus

inspect measures a fresh frame and writes a small preview, without saving a capture.

capturefab inspect -c sim:0
capturefab inspect -c sim:0 --set exposure=20ms --region 0.25,0.25,0.5,0.5
capturefab inspect -c sim:0 --keep 5m --preview none
capturefab --json inspect -c sim:0 -v --preview none
capturefab watch -c sim:0 --show

The result gives brightness as fractions of full scale (mean, p1, p50, p99), the shares and counts of pixels at black and full scale (clipped_low, clipped_high, clipped_low_px, clipped_high_px), counted over every pixel at the frame's own bit depth, a verdict list of one or more of ok, dark, bright, clipped_high, clipped_low, not_settled and not_measured (such as ["ok"] or ["clipped_high","bright"]; the frame is fine when it is exactly ["ok"]) and, when exposure is off, suggest: how many stops to move and the exposure to try. focus.sharpness is the variance of the Laplacian; compare it between frames of one camera and scene. -v adds a 16-bin histogram, color channels and the Tenengrad, Brenner and variance focus measures.

--set changes settings first, as set does, then measures a frame taken after the change. --region X,Y,W,H measures part of the frame, in fractions 0 to 1. The preview is a JPEG (longest edge --size, default 768) in a private folder that doctor names; --preview PATH writes it elsewhere and --preview none skips it. For a focus or aiming loop, the camera stays open between calls (60 seconds, or --keep 5m), and --for 10s --every 200ms measures a series and returns the sharpest frame's measurements and preview. The measured frame is always one exposed after the camera's last settings change; --fresh N lets N more pass. A camera that sets its own exposure (a webcam, a stream, ExposureAuto=Continuous) gets up to --warmup (default 2s) to settle after it starts; not_settled in the verdict says it had not. --clip-threshold sets the share of pixels at full scale that makes the verdict clipped_high. watch measures continuously instead: in a terminal it redraws the measurements in place, and with --show the frame under them; otherwise, as with --json, it prints one JSON line per measurement (--every, --for).

Cameras

Auto exposure

auto settles exposure and gain, then holds them.

capturefab auto -c sim:0
capturefab auto -c sim:0 --timeout 10s
capturefab auto -c sim:0 --off
capturefab capture -c sim:0 --auto -o settled.png

auto uses the camera's own auto exposure once when it has one, and otherwise adjusts exposure and gain itself until the brightness settles or --timeout ends. The result reports settled, the exposure and gain it holds, and limited_by when a limit stopped it; settled: false still exits 0. --off turns the camera's auto exposure, gain and white balance off and keeps their values. --continuous leaves the camera's continuous auto exposure on; for cameras without one, Capturefab's own loop runs only in a session. Cameras without exposure control, such as thermal and line scan sources, exit 5 unsupported, as does a camera that sends frames only when triggered; a trigger whose source is the camera's own timing (Freerun or FixedRate) holds no frames back.

Cameras

Triggered capture

With a software trigger, capture fires it; with a hardware trigger, it waits for the line.

capturefab capture -c 'sim:0?line0=every:500ms' --set trigger=software -o part.png
capturefab set -c 'sim:0?line0=every:500ms' trigger=line0:rising --keep 5m
capturefab capture -c 'sim:0?line0=every:500ms' -o 'part-{seq}.png' --timeout 30s
capturefab capture -c 'sim:0?line0=every:500ms' -n 1000 -o 'station/{time}.png' --timeout none --background
capturefab jobs stop all
capturefab set -c 'sim:0?line0=every:500ms' trigger=off

sim:0?line0=every:500ms is a simulator whose Line0 input fires every 500 ms; on plain sim:0 the line never fires (see simulated cameras). The trigger control sets TriggerMode, TriggerSource and TriggerActivation of the frame-start trigger together. A hardware-triggered capture waits up to --timeout for each frame (default 5s); expiry exits 4 with trigger_timeout and the trigger configuration in error.details.trigger. --timeout none waits until the capture is stopped, and inspect --timeout none waits for its triggered frame the same way. Run a long triggered capture with --background and watch it with jobs. The trigger setting stays for the captures that follow: a camera keeps its settings, and a simulator or webcam keeps the ones Capturefab emulates for it until its runtime folder is cleared.

Capture & record

Capture images

capture saves one frame, a burst, a time lapse or a delayed capture, and never overwrites a file.

capturefab capture -c sim:0 -o shot.png
capturefab capture -c sim:0 -n 10 -o frames/
capturefab capture -c sim:0 -o shot.jpg --quality 85
capturefab capture -c sim:0 -o frames/ -f raw
capturefab capture -c sim:0 --set exposure=20ms --set gain=6 -o bright.png
capturefab capture -c sim:0 -o - > frame.png
capturefab capture -c sim:0 -o shot2.png --dry-run
Image formats
FormatUse
pngThe default: lossless; 16-bit gray for monochrome frames wider than 8 bits (Mono10 to Mono16, packed or not), 8-bit gray for other monochrome, 8-bit RGB for color and Bayer. Carries tags and camera settings in its metadata.
jpgSmaller files; --quality 1–100, default 90. Carries tags and camera settings. A Motion JPEG webcam, stream or file gives the JPEG it sent, as it was, at its own quality, and the result says "passthrough": true; --quality encodes the frame again.
rawThe frame's bytes exactly as the camera sent them, at full bit depth: Bayer data, depth and thermal samples, and for webcams, streams and files the format FFmpeg decodes them to (gray, YUV or RGB). A NAME.json sidecar names the pixel format, its PFNC code, the size and the row length, or each plane's offset and rows for planar layouts.

Every common PFNC pixel format converts (see the pixel format table). The result reports bit_depth, and source_bits when the file keeps fewer bits than the frame, such as a 12-bit Bayer frame saved as 8-bit PNG or JPEG.

The format comes from the -o extension; -f chooses it when the name has none. A folder (existing, or ending in /) gets names like {camera}-{time}-{seq}.png. Without -o, files go to the current folder. -o - writes one image to stdout; with --json the result then goes to stderr.

--timeout is how long to wait for each frame (default 5s). --set and --auto change the camera first. A file name that exists exits 1 with exists; add {seq} or pass --on-exists number. Repeat -c to capture from several cameras at once: each is armed first, then all are asked for a frame at the same moment; the JSON result holds cameras, one entry each, and skew_ms, how far apart their first frames arrived. GigE cameras that share a network adapter are paced to a share of it (bandwidth_mbps). Ctrl-C stops a capture with exit 130, and error.details.files lists what was saved.

capturefab capture -c sim:0 -o measured.png --inspect --manifest shots.jsonl
capturefab capture -c sim:0 --set exposure=20ms --fresh 2 -o after.png
capturefab capture -c sim:0 -n 100 -o 'scratch/{seq}.raw' --sync none

The result says which frame each capture is: time (RFC 3339) and device_ts_ns, the camera's own clock where it has one. frames counts the frames the camera delivered while the capture ran, dropped those lost, and incomplete and resent what the transport received incomplete or asked for again, where it counts them; a burst adds fps, first_id, last_id, gaps and consecutive. The first frame saved is always one exposed after the camera's last settings change (after_change when frames were let pass for it), and --fresh N lets N more pass. A camera that sets its own exposure gets up to --warmup (default 2s) to settle after it starts: warmup_ms says how long it took, and settled: false with a warning that it had not. --inspect measures the last frame as inspect does, in the result's inspect block. --manifest FILE appends one JSON line per saved file with its path, time, size, SHA-256, settings and tags. Each file reaches the disk before it is reported; --sync none skips that for scratch captures a power cut may lose.

Name files and tag captures

Templates in -o build file names from the camera, time, sequence and your tags.

capturefab capture -c sim:0 -n 10 -o 'parts/{date}/{tag:part}-{seq:4}.png' --tag part=A-100 --tag station=3
capturefab capture -c sim:0 -o 'labels/{tag:label}/{seq:5}.png' --tag label=defect
capturefab capture -c sim:0 -o shot.png --on-exists number
Output placeholders
PlaceholderValue
{camera}The camera's model and serial, safe for file names
{serial}The serial number
{seq}, {seq:N}1, 2, 3 …, padded to N digits (4 by default)
{time}The time, such as 20261031-142233.123
{date}The date, such as 2026-10-31
{tag:KEY}The value of --tag KEY=VALUE
{ext}png, jpg or raw

Tags also go into each PNG and JPEG with the camera's settings. Paths are resolved against the folder you run the command in, also when a session does the work. Capturefab never overwrites a file: with {seq} it takes the next free number, and --on-exists number adds -0001, -0002 … to a fixed name. Read the plant-floor guide for naming that analysis tools can read.

Capture & record

Time lapses and delayed captures

--every spaces frames, --for or -n bounds them, and --at or --in delays the start.

capturefab capture -c sim:0 --every 10s --for 1h -o 'lapse/{seq}.jpg' --background
capturefab capture -c sim:0 -n 100 --every 2s -o 'lapse/{seq:5}.png'
capturefab capture -c sim:0 --at 06:00 -o morning.png
capturefab capture -c sim:0 --in 5m -o later.png
capturefab jobs
capturefab jobs wait ID --timeout 10m
capturefab jobs stop ID

Durations need a unit: 250ms, 2s, 5m, 1h30m. --at takes HH:MM[:SS] in local time or an RFC 3339 time. Without --background the command runs until the series ends; with it, a session runs the job and the command returns it once it is armed or has saved its first frame (on a triggered camera, add --timeout none so it does not wait for a trigger). Pass the ID it prints (job.id with --json) to jobs wait ID and jobs stop ID: IDs count on across a session's jobs and its runs, so another ID may name an earlier, finished job. See sessions and jobs.

Capture & record

Record and stream video

record writes video to a file or streams it to a server through the bundled FFmpeg.

capturefab record -c sim:0 -o clip.mp4 --for 30s
capturefab record -c sim:0 -o clip.mkv --codec ffv1 --for 5m
capturefab record -c sim:0 -o clip.mp4 --bitrate 4M --max-size 2G
capturefab record -c sim:0 -o rtsp://localhost:8554/cam --background
capturefab record -c sim:0 -o 'srt://localhost:8890?streamid=publish:cam' --for 10m

Files can be .mkv, .mp4, .mov, .ts or .webm, and must not exist. Streams go to rtsp://, srt://, rtmp:// or udp:// receivers such as MediaMTX. --codec h264 (the default) uses a hardware encoder where one works and libx264 otherwise; hevc and av1 need a hardware encoder, unless the source is copied (below), and exit 5 before recording without one; ffv1 is lossless, in .mkv, and stores a Bayer camera's mosaic itself as gray samples.

An H.264 or HEVC stream, video file or webcam mode is recorded as it arrives, without decoding or re-encoding its video: the result says "encoder":"copy" and the source's codec. The file starts at the source's last key frame, so it can begin up to one key-frame interval before the command. --codec naming another codec, --fps or --bitrate encodes instead. Windows always encodes. The source is still decoded while it is copied, for captures and inspection.

Recording runs until --for ends, --max-size is reached or you press Ctrl-C, which is a normal end. The result reports frames, dropped, fps_actual, the codec and encoder used, why it ended and whether the file was finalized. --fps sets the frame rate written (default: the camera's).

Capture & record

Save and restore settings

A preset keeps a camera's settings on this computer and restores them as one change.

capturefab preset save bench -c sim:0 --note 'ring light 60%'
capturefab preset list
capturefab preset apply bench -c sim:0 --dry-run
capturefab preset apply bench -c sim:0
capturefab preset export bench -o bench.json
capturefab preset import bench.json --name bench2

apply writes every saved value as one change and puts every value back if one fails. --dry-run shows what would change, with disruptive changes (triggering, I/O lines, acquisition rate) marked. --strict changes nothing when a saved value does not fit the camera. --allow-other-model applies the settings two models share. --persist then saves the result in the camera's user set and makes it the power-on default. A preset lives on this computer; a user set lives in the camera.

Capture & record

Password-protected cameras

login add saves a stream's user name and password in the OS credential store.

printf '%s\n' "$PASSWORD" | capturefab login add rtsp://cam.local/stream --user admin --password-stdin
capturefab login list
capturefab onvif resolve cam.local
capturefab login rm rtsp://cam.local/stream

login add connects once and saves the sign-in only if the camera accepts it (--no-check skips that). The password comes from --password-stdin or CAPTUREFAB_CAMERA_PASSWORD, never the command line. Every later command for that address uses it. A camera that asks for a sign-in exits 3 with auth_required, and one that refuses it with auth_rejected.

FFmpeg takes RTSP credentials only in its input URL, so other local users can read them in its command line. Plain RTSP Basic authentication and ONVIF over http:// send the password readably over the network; prefer rtsps://, Digest authentication and fixed addresses on trusted networks. onvif resolve lists an ONVIF camera's profiles and RTSP streams.

Automate

Sessions, --keep and jobs

A session keeps cameras open between commands and runs background jobs.

capturefab inspect -c sim:0 --keep 5m
capturefab session start --name bench -c sim:0 --live
capturefab session status bench
capturefab capture -c sim:0 --every 10s --for 1h -o 'lapse/{seq}.jpg' --background
capturefab jobs
capturefab session stop bench
capturefab serve --name line1 -c sim:0 --live

Each camera runs in a worker process of its own. Every camera command keeps its camera warm: it starts or reuses a session named auto that holds the camera until it has been unused for 60 seconds, so the next commands skip connecting. --keep DUR holds it longer; --keep 0, CAPTUREFAB_KEEP=0 or --no-session open and close the camera in the command alone, as on a computer without a writable runtime folder. Results are the same either way. session start starts a named session in the background that ends after --idle unused (default 30m); serve runs one in the foreground with no idle limit, for systemd. --live keeps the cameras streaming, so captures take the newest frame at once.

A command uses a session that holds its camera on its own. --session NAME picks one (also CAPTUREFAB_SESSION), and --no-session never uses one. A camera another process holds exits 3 with camera_busy, naming the holder. capturefab shell -c CAM runs many commands with the cameras kept connected: a prompt with history and Tab completion in a terminal, or one command per line of stdin (or -e) with one result per line. --background on capture or record returns a job: jobs lists every session's jobs (jobs list ID... only those, --running only those not ended), jobs wait ID... exits 0 when the jobs are done (4 while one still runs) and jobs stop ID ends one, keeping the files. session stop does not wait for jobs: those still running end as interrupted, keeping their files. A job is armed, running or stopping, then done, failed, cancelled or interrupted; the jobs of a session that died are listed as lost. session status lists each camera's state, frame counts and jobs, and for a camera whose worker exited, an error (worker_crashed with its exit status and the last lines it wrote); the next command on that camera starts another worker. debug rpc sends one session command, a JSON object on stdin such as {"op":"status"}, {"op":"jobs"}, {"op":"wait","job":"auto-1","timeout_ms":5000} or {"op":"stop_job","job":"auto-1"}, and prints its reply; it is for debugging, and its commands can change between releases. The line computer guide runs a session at boot.

JSON results and exit codes

With --json, every command prints one JSON document and exits with a typed code.

capturefab --json get -c sim:0 ExposureTime 'TriggerMode[FrameStart]'
capturefab schema
capturefab schema set
capturefab completions zsh > ~/.zfunc/_capturefab

Exit 0 means stdout holds the result. Any other exit means it holds {"error":{"code","message","hint"?,"details"?}}, also for a mistyped option. Logs and progress go to stderr. Keys use snake_case with units in their names (exposure_us), times are RFC 3339 UTC, and lists are bounded with a truncated count. CAPTUREFAB_JSON=1 turns JSON on for every command.

GigE network checks

network checks how each GigE camera is reached; --tune shares bandwidth between cameras.

capturefab network
capturefab network --tune -c gige:00c0df123456 -c gige:00c0df654321

network lists the IPv4 adapters with their MTU and link speed, and each GigE camera found with the adapter that reaches it and a health summary. It changes nothing. --tune sets packet delay or throughput limits on the named cameras so they share a link without losing packets; they keep the setting until they power off. Host addresses, routes and MTUs are never changed. Give camera networks their own wired adapter where you can, and on Linux raise net.core.rmem_max as doctor suggests.

Check this computer

doctor prints one line per check, with a copyable fix under each warning.

capturefab doctor
capturefab --json doctor

The checks cover the bundled FFmpeg (webcams, streams, files and recording need it), the folders Capturefab uses, wired adapters for GigE Vision and, on Linux, the GigE receive buffer, USB3 Vision device access and where a service keeps its sessions. --json adds the build's features, the FFmpeg in use and dirs: runtime (sessions), state (presets, sign-in records), cache (FFmpeg) and inspect (previews); jpeg, the JPEG encoders and whether each hardware engine (Apple's, nvJPEG, VA-API) is on this computer and passed its accuracy check here, or why not; and hwdec, each hardware decoding method and whether it decodes here.

Troubleshooting

Read error.code and error.hint first; doctor checks the computer.

capturefab doctor
capturefab --json list
capturefab session list
capturefab -v info -c sim:0
A camera is missing or cannot connect

Read the warnings of list and use the camera's full ID. For GigE, network checks reachability on its subnet. For USB3 Vision, check operating system access: doctor prints the Linux udev rule, and on Windows the camera must use WinUSB. On macOS, a camera at a correct address that reports no route to host can mean Local Network access was denied to your terminal app.

camera_busy: another process holds the camera

A session or another command has the camera open; error.details.held_by names it when known. Run the command through that session (--session NAME), wait for its job, or stop it with jobs stop or session stop.

frame_timeout or trigger_timeout

Make sure the camera streams and that its trigger can supply frames: info shows the trigger. Raise --timeout for slow sources, or set trigger=off. For GigE, packet loss looks like timeouts: check the receive buffer and network.

A setting is locked or rejected

feature_locked names the setting that locks it in details.locked_by; change that first. Some features can change only while the camera is not streaming. set --dry-run shows what a change would write.

A frame's pixel format is unsupported

Choose another PixelFormat the camera offers, or capture raw to keep the bytes as they are. The pixel format table lists the supported formats.

A stream, video file or encoder fails

doctor shows whether FFmpeg runs. Make sure a receiving server is up and reachable. hevc and av1 need a working hardware encoder; h264 always has libx264. A development build can use CAPTUREFAB_FFMPEG=/absolute/path/to/ffmpeg.

An SSH shell cannot find a session a service started

Without XDG_RUNTIME_DIR, a Linux service uses /run/user/<uid> only when its user lingers. Run sudo loginctl enable-linger USER and give the service Wants= and After=user@<uid>.service. doctor in the SSH shell says where a service keeps its sessions.

Capture stops with storage_full

A write would have taken the disk below the free space Capturefab leaves for the system: 1% of the disk, at least 512 MiB and at most 20 GiB. error.details gives the path and its free_bytes. Free space or capture to another disk; CAPTUREFAB_MIN_FREE (bytes or a size such as 2G, 0 for none) changes the floor. Capturefab never deletes files to make room.

For a bug report, include capturefab --version, the operating system, the camera type, the exact command and its JSON output, and capturefab --json doctor. Remove private addresses and names before you share them.

Motion JPEG is decoded with libjpeg-turbo whatever it says.

A session's cameras keep the CAPTUREFAB_JPEG, CAPTUREFAB_HWDEC and CAPTUREFAB_FFMPEG the session started with, the warm auto session included: stop it with capturefab session stop auto, or use --no-session, for a command to use other values. Where a default folder cannot be written, as on a read-only root file system, Capturefab falls back to a private folder in a tmpfs and turns off only what needs the missing folder; the embedded and read-only hosts guide lists each case.

Build, architecture and licensing

One Rust executable; each camera runs in a worker process of its own, and FFmpeg runs as a separate executable.

Capturefab implements GigE Vision, USB3 Vision and GenICam in Rust. Every camera command reaches its camera through a worker process, started by the command itself or held by a session, so a camera driver that hangs or crashes cannot take other cameras down. Webcams, streams, files and video encoding use the embedded FFmpeg, run as a separate process. This is an early implementation: it does not provide every feature of Aravis or vendor SDKs, and behavior can change between releases.

Build from source

Install a stable Rust toolchain, a C compiler and CMake, and on x86 NASM for libjpeg-turbo. Webcams, streams, files and recording need FFmpeg. A build embeds the FFmpeg named by CAPTUREFAB_FFMPEG_BINARY, or in release builds target/ffmpeg/<target>/bin/ffmpeg when it exists, which scripts/build-ffmpeg.sh builds from the pinned sources (this takes a while); cargo build never builds FFmpeg itself. At run time Capturefab uses CAPTUREFAB_FFMPEG, else the embedded copy, else an ffmpeg next to the executable or on PATH.

tar -xzf capturefab-VERSION-source.tar.gz
cd capturefab-VERSION
cargo --config .cargo/vendor-config.toml build --release --offline --locked
target/release/capturefab capture -c sim:0 -o first.png

The default features are usb (USB3 Vision), jpeg (libjpeg-turbo), videotoolbox (Apple's JPEG engine on macOS), nvjpeg and vaapi (the GPU JPEG encoders on Linux, whose libraries are loaded at run time in a helper process, so a build needs no SDK), keychain (the OS credential store for login) and shell (line editing in capturefab shell); --no-default-features builds without them, and doctor --json lists what a build has.

Licensing and release provenance

Capturefab uses the MIT license. The embedded FFmpeg is GPLv3 with x264, SRT, OpenSSL and zlib; capturefab licenses prints both notices. See the FFmpeg build and compliance guide. The downloads page shows how to verify each file, and the release manifest lists files, checksums and build metadata.
