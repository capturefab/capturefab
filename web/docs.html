Start here

Your first capture

Connect a camera. Examine its image. Save a frame. The built-in pattern camera supplies images without camera hardware.

  1. Install and open the desktop app for your operating system and processor.
  2. Enter sim:0 in the camera address field.
  3. Push Enter to connect the pattern camera.
  4. Select the camera.
  5. Open Features to examine its settings.
  6. Open Capture.
  7. Keep File names at By date, camera and time (recommended), with Frames at 1 and Format at PNG.
  8. Select Capture & save.

Capture acquires a frame when the preview is stopped. The path below the save button shows the saved file. Each capture gets a new name, and Capturefab does not overwrite existing files.

# The same first capture from a terminal
capturefab --camera sim:0 capture -o first.png

# Examine the simulator, then capture a sequence
capturefab --camera sim:0 features
capturefab --camera sim:0 capture -n 10 -o first-frames

These commands automatically use the only active desktop or headless session. Its preview and Activity show the work. Without an active session, capture uses a temporary camera worker. Use --direct for a temporary worker. With several sessions, use --session NAME. Local output paths use the directory of the terminal that sends the command.

Screenshots show the current development app with simulator sources. Controls can differ by release.

Capture plant data for analysis

Collect images, video, sensor values and PLC tags on a production line. Keep them in one dataset file. Export the data for a notebook, a BI tool or an AI assistant.

Capturefab runs on one computer on the OT network. It does not use a cloud service. Each saved image and recording gets a row in the dataset, with its time, camera, path, SHA-256 and tags. Signal samples go into the same file. A view matches each capture with the latest value of each tag at that time.

  1. Connect the cameras. Use sim:0 to try the steps without camera hardware.
  2. In Capture, expand Live signals.
  3. Enter a source URI in Add data source, for example sim-signal://line1.
  4. Expand Capture tags. Enter the Line, Station, Part, Lot or Note.
  5. Select Capture & save or Record. Each file gets a new name.
  6. Expand Dataset to see the catalog. Select Export… at the end of the run.

With Catalog captures automatically on, the app makes ~/Capturefab/capturefab.duckdb at the first saved file or signal sample. The export folder contains Parquet and CSV files, manifest.json and README.md. Give the README.md and manifest.json to the analysis tool first. They describe each table, unit and time base.

# The same run from a terminal, with simulators
capturefab serve --name line1 --dataset plant.duckdb
# In another terminal:
capturefab --session line1 signals start sim-signal://line1
capturefab --session line1 --camera sim:0 capture \
  -o 'line1/{date}/{camera}-{datetime}-{seq}.png' --context part=A-100
capturefab --session line1 dataset note "nozzle changed" --context line=L1
capturefab --session line1 dataset export -o exports/line1-shift-b

See File names and tags, Sensors and PLCs and Datasets and exports for each step. The plant-floor guide gives the full procedure. Capturefab does not claim compatibility with a specific camera, PLC, broker or server.

Install and verify a release

Choose a desktop build for the app and command-line interface (CLI). Choose a headless build for a computer without a display.

The download page lists release files and their SHA-256 checksums. Select the build for your installed operating system and processor architecture. Apple silicon uses ARM64. Intel and AMD PCs usually use x64. On Raspberry Pi and Jetson, a 64-bit processor can have a 32-bit operating system.

Verify the downloaded file
SystemCommand
Linuxsha256sum DOWNLOADED_FILE
macOSshasum -a 256 DOWNLOADED_FILE
Windows PowerShellGet-FileHash DOWNLOADED_FILE -Algorithm SHA256

Compare the result with the checksum for the same release file. Then extract the archive. Keep the included license files with the application.

Open the extracted desktop build
SystemSteps
macOSExtract the .zip file. Open Capturefab.app from the extracted folder. You can move it to Applications.
WindowsExtract the .zip file. Open capturefab.exe from the extracted folder. In PowerShell, run .\capturefab.exe from that folder.
LinuxExtract the .tar.gz file. Open a terminal in the extracted folder. Run ./capturefab. If necessary, set executable permission with chmod +x ./capturefab.

The extracted executable also provides the CLI. Add its directory to your PATH to use the shorter commands in these guides. A headless build opens no desktop window. Use an explicit subcommand such as doctor --json or serve. To run serve as a service on a Raspberry Pi, Jetson or industrial PC and use it from a laptop's browser, follow the line computer guide.

Minimum operating system versions
BuildMinimum requirement
macOS ARM64macOS 11.0
macOS x64macOS 10.15
Windows x64Windows 10; Windows 11 on ARM can use x64 emulation.
Windows ARM64Windows 11 on ARM
Linux x64 and ARM64glibc 2.28; examples include Debian 10, RHEL 8 and Jetson Linux R34.

These minimums also apply to the included FFmpeg executable. A separate Visual C++ redistributable is not necessary for Windows builds. There is no 32-bit ARM build: on Linux, dpkg --print-architecture prints arm64 for the ARM64 build, while armhf, such as 32-bit Raspberry Pi OS, needs the 64-bit OS, which Raspberry Pi 3 and later run. uname -m prints aarch64 on both. See the release target details for build requirements.

Release builds include a separate FFmpeg executable. Separate Aravis, FFmpeg, libusb, vendor SDK and Python installations are not necessary. The operating system must have suitable graphics and camera drivers. Document scanners have additional driver requirements.

# Optional: verify GitHub build provenance
gh attestation verify DOWNLOADED_FILE --repo capturefab/capturefab

Understand the workspace

The camera list, preview and inspector keep connection, image and settings in view. Select a camera to make its controls active.

Camera list
Find discovered, connected and recently used sources. Enter an IP address, stream URL or video file to connect directly.
Preview stage
See connected cameras together, then open one camera for a larger view. Streaming state, frame rate and errors belong to each camera.
Inspector
Features edits camera settings, Capture saves images and schedules, and Video records video or publishes a stream. Common controls appear first; expand the labeled sections for additional settings.
Activity
See human and AI agent actions across the session’s cameras, including progress, saved files and full errors.

When no input field has focus, push Enter to open the selected camera. Push Esc to return to all cameras. Use the bottom toolbar to show or hide the camera list, settings and Activity. See Keyboard shortcuts for the related keys.

The app uses your system’s light or dark appearance. It saves workspace settings and recent camera addresses. It does not save addresses with credentials or secret query parameters. To set the appearance at startup, use CAPTUREFAB_APPEARANCE=light or dark.

Connect & examine

Find and connect cameras

Discovery lists GigE Vision, USB3 Vision, native and ONVIF cameras, and document scanners. Connect a listed source or enter its address.

  1. Run discovery from the camera list.
  2. Read the discovery warnings.
  3. Select a listed camera to connect it.
  4. Select its tile or list entry to examine it.
  5. Start its stream for a continuous preview.

Stop acquisition before you change camera geometry or a native video mode. Camera compatibility describes connection requirements and unsupported paths.

capturefab discover --json
capturefab native --json           # webcams and capture cards
capturefab onvif discover --json   # ONVIF devices on the LAN
capturefab scanners --json
capturefab --simulate discover    # include the pattern camera

# Reuse an open desktop session
capturefab sessions
capturefab --session gui connect sim:0
capturefab --session gui start

Camera selectors accept a discovered ID, unique serial number or GigE IPv4 address. A GigE camera must have a reachable address on the camera’s subnet. USB3 Vision must have userspace access. Linux must have USB permissions; macOS must have an available IOKit interface; Windows must have WinUSB. Camera permission from the operating system can be necessary for native webcams.

Camera commands automatically use the only active GUI or headless session. With several sessions, use --session NAME. Use --direct --camera ID for a temporary connection. Camera control can be exclusive. If the app has the camera open, use its session.

--camera ID targets a camera and keeps the visible selection. select ID sets the session default for CLI calls without --camera. Desktop windows and browser tabs each keep their own selection. disconnect releases the addressed camera.

Camera and media source locators

A source locator identifies the camera, stream or file to open. Put locators with spaces or URL query parameters in quotation marks.

Source examples

Choose a native camera mode

Native locators accept ?size=1280x720&fps=30. Examine Features for the available VideoMode choices. Before you start acquisition, set a supported mode or supported Width, Height and AcquisitionFrameRate values. Available modes depend on the driver. V4L2 format listings do not establish frame-rate limits.

capturefab --camera 'avfoundation:0?size=1280x720&fps=30' capture -o webcam.png
capturefab --camera 'rtsp://camera/live' capture -o network.png
capturefab --camera '/path/to/clip.mp4' capture -o video-frame.png
capturefab onvif resolve 'http://camera/onvif/device_service' --username admin --json

For ONVIF, supply the password through CAPTUREFAB_CAMERA_PASSWORD. Authenticated locators also accept onvif://USER:PASS@HOST/onvif/device_service. Use percent encoding for reserved characters. The interface and status output remove credentials from view, but your shell can record typed secrets. HTTPS SOAP and Media2-only devices are unsupported.

HDMI capture devices use their operating system video driver. CSI cameras must have an accessible video device with a supported driver. Capturefab does not implement libcamera-only pipelines or proprietary camera tethering protocols. capturefab compatibility MODEL gives connection guidance. It does not certify camera compatibility.

Camera types and measurement data

The interface adapts to area-scan, line-scan, depth, microscope, thermal and document-scanner profiles. A profile identifies available control families. It does not prove physical camera compatibility or writable access. Examine the current feature list and limits before you change a setting.

Expand Camera details in Features to read acquisition guidance and the evidence used to detect the camera type.

Line-scan previews show recent rows, with gaps for skipped blocks. Captures save individual acquired blocks. Depth and thermal previews show colors for an automatic raw-value range. These colors do not apply measurement calibration. Select Sensor pixels to return to the ordinary preview.

For depth or temperature measurements, use --format raw. Keep dimensions, pixel format, selected component, units, scale, offset and calibration features separately. Raw files preserve acquired bytes without that metadata. PNG, JPEG, PGM, PPM and forwarded video are 8-bit display outputs. Depth sources must have a compatible single-component stream; multipart, GenDC and point-cloud payloads are unsupported.

Use sim:line, sim:depth, sim:microscope or sim:thermal to try the specialized controls without camera hardware. See Camera compatibility for profile and transport limits.

Connect & examine

Scan documents

Scanners use the same capture, preview, destination, schedule and storage tools. Each capture requests one page.

Discover a scanner. Connect its full ID. In Features, select Scan resolution, Scan mode and Scan source. Open Capture. Select Scan & save. A connection or acquisition start does not scan a page.

Scanner controls
FeatureValuesDefault
ScanResolution75–600 dpi150
ScanModeColor, Gray, LineartColor
ScanSourceDefault, Flatbed, FeederDefault, leaving the driver’s source unchanged
capturefab scanners --json
# Replace DEVICE with the full returned scanner ID
capturefab --camera 'scanner:sane:DEVICE' --timeout-ms 60000 capture \
  --set ScanResolution=300 --set ScanMode=Gray --set ScanSource=Feeder \
  -n 5 -o pages

Linux uses the installed SANE scanimage and backends. CAPTUREFAB_SCANIMAGE sets the executable path. Windows uses a WIA driver through Windows PowerShell. macOS uses an included ImageCaptureCore helper and a compatible driver.

Drivers can reject unsupported settings. Capturefab does not select a different mode after a rejection. Use Default if a SANE driver has source names other than Flatbed or Automatic Document Feeder.

The GUI scanner timeout defaults to 60 seconds. For CLI scans, use --timeout-ms 60000. A timeout, stop or disconnect terminates acquisition. A capture with several pages saves a separate image for each page. Samples use 8-bit RGB or grayscale, with a 128 MiB page limit.

Scanner sources do not support PDF assembly, OCR, stream forwarding or camera auto exposure. Physical scanner compatibility has not been validated.

Read sensors and PLCs

Read values from Modbus TCP, MQTT, OPC UA and MTConnect sources. Log them with your captures. Each source is one URI.

  1. Open Capture and expand Live signals.
  2. Enter the source URI in Add data source.
  3. Push Enter to start the source.
  4. Read each tag’s value, unit and trend line.
  5. To stop a source, select its stop button in the Data sources list in the sidebar.
Signal source URIs
ProtocolURI
Modbus TCPmodbus-tcp://HOST[:502]/UNIT/holding/ADDRESS?type=f32&name=TAG&unit=UNIT; tables coil, discrete, input, holding
MQTTmqtt[s]://[USER[:PASS]@]BROKER[:1883]/TOPIC_FILTER
OPC UAopc.tcp://HOST[:4840]?node=NODE_ID[&node=...]
MTConnectmtconnect[s]://HOST[:5000][/DEVICE]
Simulatorsim-signal://LINE
capturefab signals read sim-signal://line1
capturefab signals read 'modbus-tcp://10.0.0.20/1/holding/0?type=f32&name=temp_c&unit=degC'
capturefab signals browse opc.tcp://10.0.0.30:4840 --duration 5s
capturefab signals browse 'mqtt://broker.local/plant/#' --duration 10s

# Log for 10 minutes into a dataset and a CSV file
capturefab log sim-signal://line1 --interval 1s --duration 10m \
  --dataset plant.duckdb --csv line1.csv

# Keep sources in a running session
capturefab --session line1 signals start sim-signal://line1 --interval 1s
capturefab --session line1 signals
capturefab --session line1 signals stop all

Modbus addresses start at 0. Modicon register 40001 is holding/0. A value is the raw value multiplied by scale, plus offset. MQTT accepts numbers, true or false, JSON objects and text. Capturefab changes JSON fields into tags such as topic/field. MTConnect tags are DEVICE/DATA_ITEM_ID.

OPC UA uses SecurityPolicy None only. A password in the URI travels without encryption. Capturefab removes credentials from all output and saves only recent URIs without credentials. Use percent encoding for @ in topics and node IDs.

Each source runs in a separate helper process. If a source stops, Capturefab starts it again a maximum of five times. A session holds a maximum of 16 sources. signals start and signals stop must have a running GUI or serve session. log must have --csv, --dataset or both. Browse is not available for Modbus.

ts_ms is the computer clock in UTC milliseconds when the value was read. source_ts_ms is the device clock. Without a dataset or CSV file, the session keeps only the latest values. Capturefab reads values. It does not write to devices.

Connect & examine

Examine and change camera features

The Features panel reads the camera’s current feature map. It shows values, access permissions, choices, limits and units.

  1. Select a connected camera.
  2. Open Features.
  3. Use Quick controls, expand a feature group, or search by feature name, display label or description.
  4. Edit a numeric or text value.
  5. Push Enter or select Apply.
  6. Read back the accepted value.

Choice menus and checkboxes apply changes immediately. A camera can round a value to its supported increment. A rejected write shows its reason beside the field.

Less common controls stay in groups such as Image, Acquisition, Device, Transport and Other. Each group shows its feature count. Search reveals matching controls across the groups, including groups you have kept closed. Clear the search to return to Quick controls and your expanded groups. Names and available features depend on the source. Put the pointer on a label to see its feature name and description. For settings that acquisition locks, the Locked while streaming notice provides a Stop button.

capturefab --camera sim:0 features --filter Exposure
capturefab --camera sim:0 get Width Height PixelFormat ExposureTime
capturefab --camera sim:0 set ExposureTime=5000 Gain=0
# A camera command, when the device exposes it
capturefab --session bench execute TriggerSoftware

CLI assignments run in the specified order. A later failure does not reverse earlier successful writes. Examine the features before a write. Read back important values after a write. A manual edit to an Auto-managed feature changes that camera to manual mode. Use Undo and Redo for acknowledged, reversible settings.

Connect & examine

Tune auto exposure and frame rate

Enable Auto for one camera. Select the balance between image quality and frame rate. Cameras start in manual mode.

In Features, select Auto on the Exposure card. Move the slider toward Quality for longer exposure with less gain. Move it toward Frame rate for shorter exposure with more gain. The default balance is 0.5, at the midpoint.

Auto uses the camera’s automatic exposure, gain and white balance controls when available. Otherwise, Capturefab adjusts exposure and gain. If link capacity permits, Auto can increase frame-rate or GigE throughput limits. It reduces these values if packet loss occurs. Expand Auto changes to see each change and its reason.

Stable and Limited are settled states. Waiting means that acquisition is stopped.

capturefab --session bench auto --balance quality
capturefab --session bench auto --balance 0.5
capturefab --session bench status --json
capturefab --session bench manual
capturefab --session bench manual --revert

capturefab --camera sim:0 capture --auto --balance 0.25 -o tuned.png

manual disables camera auto functions and keeps their current values. manual --revert restores the settings that Auto changed. Disconnect, direct-command exit and session exit also restore those settings where possible. In a persistent session, capture --auto keeps Auto enabled after capture.

For capture --auto, Capturefab applies repeated --set assignments first. It waits for exposure to settle for half the transport timeout, with a maximum wait of 3 seconds. It can save a frame before exposure settles. Examine result.auto.state in the JSON result.

An image camera with suitable controls is necessary for auto exposure. It can support microscopes with those controls. Line-scan, depth, thermal and document-scanner sources do not support generic auto exposure. Configure their timing or measurement controls directly.

Connect & examine

Preview, zoom and compare cameras

Use the overview to see several live cameras. Open one camera to examine its image at a larger scale.

Connect two or more sources to show a grid. Select a camera to show its inspector. Open the camera to enlarge its preview. Push Esc outside an input field to return to the grid. Each camera acquires independently. A change of selection does not stop another camera’s stream.

  • Fit centers the entire frame in the available area. Use ⌘0 on macOS or Ctrl+0 elsewhere.
  • Actual pixels shows the image at 1:1 with ⌥⌘0 or Ctrl+Alt+0.
  • Zoom in / out uses ⌘+ / ⌘− or Ctrl+= / Ctrl+−.
  • Image only hides workspace panels. Push F when no field has focus, then push it again to return.

The live preview uses the latest frame if the display cannot keep up. Preview scale does not change the saved image resolution. The preview converts only as many pixels as the window shows, so a large sensor fitted to the window costs a fraction of its full size, and Actual pixels and closer zooms show every pixel. In efficiency mode a fitted preview keeps at most 1280 pixels on its long side, and a scaled-down one samples pixels rather than averaging them. A default session supports 16 connected cameras. CAPTUREFAB_MAX_CAMERAS accepts values from 1 to 64.

If the preview fails, open the camera’s Activity details. Troubleshooting covers frame timeouts, graphics fallback and transport diagnostics.

Connect & examine

Read the histogram and focus scores

Use the histogram to examine shadows and highlights. Use the focus region to compare image sharpness as you adjust the lens.

Histogram

Push H outside an input field to show the Histogram. It shows Mean intensity, Shadows at black and Highlights with a saturated channel. Use these measurements to help set exposure and gain. The histogram does not change camera settings. When the camera has a writable exposure time or gain, select Shadows or Highlights to open that control in Features, or the camera's own auto exposure while it runs. While a stream runs, the histogram updates five times a second and the focus score up to 15 times a second.

Focus region

  1. Push R outside an input field to show the focus region and score.
  2. Position the region over useful image detail.
  3. Adjust the region size.
  4. Choose a focus measure (Edges, Strong edges, Texture or Contrast) in the Focus card's chooser.
  5. Adjust the lens to increase the score.
  6. Compare the trend and % of peak with similar light and scene content.
  7. After a scene change, select Reset peak (the reset button on the Focus card) before a new adjustment.
Focus measures
MeasureWhat it measures
Edges (Laplacian)Variance of the Laplacian; responds to fine edges.
Strong edges (Tenengrad)Squared Sobel gradient; useful on strong edges and in noise.
Texture (Brenner)Squared differences two pixels apart; favors fine texture.
Contrast (Variance)Normalized intensity variance; a contrast measure, gentle on noise.

The score compares image sharpness. It is not a lens calibration or an autofocus command. Subject, light, gain and focus-region changes can change the score independently of lens focus.

Capture & save

Capture images and sequences

Save one frame to a file. Save several frames to a directory or a sequence with a {frame} filename template.

  1. Open Capture for the selected camera.
  2. Select a destination in Save to.
  3. Choose how files are named in File names, and where in Folder. To enter a file, folder or template, choose Custom pattern….
  4. Set Frames and Format.
  5. Select Capture & save.
  6. Read the saved path or error below the button.

The default output is ~/Capturefab/{date}/{camera}-{datetime}-{seq}.png. Each capture gets a new name. Camera and time leaves out the dated folder, and Numbered saves capture-{seq} files. A template you enter by hand keeps its field open. Next file shows the next file's path from the chosen folder. Select Show in Finder to open the folder of the last capture. On Windows the button is Show in Explorer; on Linux it is Show in folder. In the overview, Capture all saves one frame from each connected camera.

Expand Capture options to change the transport timeout. Use Capture on a schedule for delayed or interval captures. Automatic capture, Storage & retention and Shell & agents reveal their setup when you need it.

While an automatic capture session is open, its status and review appear above the manual controls.

capturefab --camera sim:0 capture -o frame.png
capturefab --camera sim:0 capture -n 10 -o frames
capturefab --camera sim:0 capture -n 10 -o 'run-{frame}.png'
capturefab --camera sim:0 capture -o 'line1/{date}/{camera}-{seq}.png'
capturefab --camera sim:0 capture -o frame.jpg
capturefab --camera sim:0 capture --set Width=640 --set Height=480 -o configured.png

# One binary image to stdout; do not combine with --json
capturefab --camera sim:0 capture -o - --format ppm > frame.ppm
Image formats
FormatUse
pngDefault lossless image output.
jpeg / jpgLossy still images at quality 90; the JPEG build feature is necessary.
rawPreserve frame bytes when image conversion is unsupported or unnecessary.
pgmPortable grayscale output.
ppmPortable RGB output.

Capturefab selects the image format from the extension of a single filename or template. It recognizes .png, .jpg, .jpeg, .raw, .pgm and .ppm. Directory sequences, outputs without an extension and stdout default to PNG. --format overrides this selection. With an unknown extension, specify the format.

Local CLI and RPC output paths use the directory of the terminal that sends the command. This also applies when the GUI starts from another directory. With --destination NAME, output names are relative to that saved destination.

--timeout-ms sets the per-frame transport timeout from 1 to 60,000 ms. Its default is 2,000 ms. --count accepts 1–100,000 frames. Capturefab does not overwrite existing output files. Use a {seq} template or --on-exists number to get a new name each time. See File names and tags. For delayed and repeated captures, see Scheduled captures.

Capture & save

Name files and tag captures

Use a template to give each capture and recording a new file name. Add tags that tell the analysis what each file shows.

Output placeholders
PlaceholderValue
{camera}Model and serial number, with only A-Z a-z 0-9 . _ -; a maximum of 64 bytes. It never contains the address.
{date}YYYY-MM-DD
{time}HHMMSS
{datetime}YYYYMMDD-HHMMSS
{seq}The next free number for that folder and pattern, with 4 or more digits.
{frame}The frame number in a multi-frame capture, with 6 digits.
capturefab --camera sim:0 capture -o 'line1/{date}/{camera}-{datetime}-{seq}.png'
capturefab --camera sim:0 capture -o shot.png --on-exists number
capturefab --camera sim:0 record -o 'video/{camera}-{seq}.mp4' --duration 30s
capturefab --camera sim:0 capture -o 'qa/{camera}-{seq}.png' \
  --context line=L1 --context station=S2 --context part=A-100

Times use the local clock when Capturefab requests the frame. Use {seq} only once and only in the file name. Do not put a digit or another time placeholder directly after {seq}. Other names in braces cause a usage error.

Capturefab never overwrites a file. Without {seq}, an existing name causes an error. --on-exists number adds -0001, -0002 and the subsequent numbers to the name. A directory output continues after its highest frame-NNNNNN number. A multi-frame template must contain {frame} or {seq}, or use --on-exists number.

The desktop app always adds a number to an existing name. Its default recording output is ~/Capturefab/{date}/{camera}-{datetime}-{seq}.mp4. Read the saved names in result.files and result.frames[].file. A recording result gives the file in path.

Capture tags

In Capture, expand Capture tags. Enter Line, Station, Part, Lot and Note as necessary. The app sends them with each capture and recording as the context keys line, station, part, lot and note. An open dataset keeps them in each row.

From the CLI, use --context KEY=VALUE once for each tag. A key starts with a lowercase letter and contains a maximum of 32 lowercase letters, digits and underscores. A capture accepts a maximum of 16 tags, with 256 bytes for each value.

Capture & save

Schedule captures and timelapses

Start capture later or capture at intervals. The session shows job progress and the next frame time. You can cancel pending or active jobs.

  1. In Capture, set the output, frame count and format.
  2. Expand Capture options and enable Capture on a schedule.
  3. Enter Start after and Frame interval in seconds.
  4. Select Schedule capture.

Scheduled jobs shows progress. Use its Stop button to cancel pending or active work.

# Direct commands wait for their job to finish
capturefab --direct --camera sim:0 capture --delay 30s -o later.png
capturefab --direct --camera sim:0 capture --interval 10s -n 360 -o timelapse

# Existing sessions return a job ID
capturefab --session bench capture --delay 5s --interval 1m -n 60 -o timed-frames
capturefab --session bench jobs --json
capturefab --session bench cancel 1

# Use a future timestamp with an explicit timezone
capturefab --session bench capture --at 2026-12-01T09:00:00-05:00 \
  --interval 1m -n 100 -o morning

Use --at or --delay to set the start time. Durations accept ms, s, m, h, d, or plain seconds. The frame count limits a timelapse. Each frame acquisition has its own transport timeout.

Durations and timestamp fractions must resolve to whole milliseconds. For example, 1.001s is valid; Capturefab rejects 1.1ms. All scheduled frames must occur within 10 years. A past timestamp starts capture immediately. A zero RPC interval captures consecutive frames. Two active jobs on one camera cannot use the same fixed filename or {frame}-only template. They can share a directory, a {seq} template or a numbered output.

Keep the GUI, headless session or direct command active. Schedules end when its process exits. The stop command stops acquisition and cancels pending capture jobs on that camera. A stopped or failed job stays visible with its progress and error.

Scheduled frames are saved in the background, so the preview, recordings and forwarding keep running while a frame saves. If a shot comes while two earlier frames still wait to be saved, the job skips it and takes it at a later interval. If the disk is briefly busy or slow, the job tries the shot again at the next interval. The job card counts skipped and retried shots. A full disk, or another save error, stops the job.

Capture & save

Catalog and export datasets

A dataset is one DuckDB file. It records each saved capture and recording, each signal sample and your notes. An export makes files for analysis.

  1. In Capture, expand Dataset.
  2. Select New… or Open…, or keep Catalog captures automatically on.
  3. Capture, record and log signals as usual.
  4. Select Export… and select a folder.
  5. Open the README.md that the app shows after the export.

The automatic dataset is ~/Capturefab/capturefab.duckdb. The app opens the same dataset at the next start. The section summary shows the file name and the number of captures and samples. Use Show in Finder to find the file. Use Close before you copy it.

capturefab --camera sim:0 capture -o 'line1/{camera}-{seq}.png' --dataset plant.duckdb
capturefab --session line1 dataset open plant.duckdb
capturefab --session line1 dataset note "shift B start" --context line=L1
capturefab --session line1 dataset status
capturefab --session line1 dataset query \
  "SELECT path, tag, value_double, sample_age_ms FROM captures_with_signals LIMIT 20"
capturefab --session line1 dataset export -o exports/shift-b
capturefab --session line1 dataset close

# A dataset that no session holds
capturefab dataset query --file plant.duckdb "SELECT count(*) FROM captures"
capturefab dataset export --file plant.duckdb -o exports/csv-only --format csv

Each *_ms column is UTC Unix milliseconds from the computer clock. The context column contains JSON text. A query accepts one read-only SELECT or WITH statement. It returns a maximum of 10,000 rows and stops after 30 seconds. A query cannot read or write other files.

An export writes into a new folder. Capturefab does not use an existing folder. The default formats are Parquet and CSV; JSON and JSONL are also available. The folder also contains captures_wide, with one column for each tag, manifest.json and README.md. The README gives the time base, the file list, loading examples and a summary for AI tools. Images and videos stay at the paths in the tables.

A session keeps the dataset file open. To read the file from another command, use --session NAME. With --file, a held file causes exit code 3. The default size limit is 8 GiB. Writes stop with exit code 6 when less than 512 MiB of disk space is free. An export that does not fit the storage budget stops before it writes a file.

Bucket credentials and providers

Select an access key from the operating system keychain, an AWS shared-credentials profile, or the upload process environment. Destination settings contain no secret keys. The CLI accepts --access-key-id with --secret-stdin to read the secret from stdin. Keep secrets out of command lines.

In the app, a new bucket asks for its service, bucket and access key, and for its region unless the service is Cloudflare R2. Advanced holds Folder in bucket (the key prefix), path-style addressing, an AWS profile or environment credentials, and the region for Cloudflare R2. It opens by itself when one of them is changed or refused. While closed, it lists what is set.

For a non-AWS service, set its --endpoint and --region. If necessary for the service, add --path-style. --prefix adds a bucket key prefix. --keep-local keeps local copies after verified upload. The s3 build feature is necessary for S3 operations.

For RustFS or MinIO on your network, select MinIO, RustFS or self-hosted. From the CLI, use --preset rustfs or --preset minio with --endpoint. The preset tests whether the service refuses to replace an object. If the service does not refuse, Capturefab looks up each key before it writes.

FTP, FTPS and SFTP servers

Add FTP and SFTP servers with the CLI. The desktop app shows them in Save to and uses them, but it does not edit them. FTP uses explicit TLS (FTPS) by default. --plain sends files and the password without encryption. SFTP must have the server’s host key fingerprint, or --accept-host-key to trust the key that the server shows now.

capturefab destination add-ftp qa-ftp --host ftp.plant.local \
  --user camera --dir images --password-stdin < password.txt
capturefab destination add-sftp qa-sftp --host files.plant.local --user camera \
  --dir /srv/images --host-key SHA256:... --key-file /home/me/.ssh/id_ed25519
capturefab destination add-s3 nas --bucket line1 \
  --endpoint http://nas.plant.local:9000 --preset rustfs --profile lab
capturefab destination test qa-sftp
capturefab --camera sim:0 capture --destination qa-sftp -o '{date}/{camera}-{seq}.png'

The keychain keeps FTP and SFTP passwords. --password-env reads CAPTUREFAB_FTP_PASSWORD or CAPTUREFAB_SFTP_PASSWORD in the upload process. With --key-file, the password is the key passphrase. SFTP writes a temporary file, then renames it only if the name is free. FTP also writes a temporary file and examines its size before the rename. Some FTP servers replace a file at rename, so use one writer for each FTP folder. If the SFTP host key changes, the upload stops.

Mounted drives appear as shortcuts in the destination selector. If an external drive is absent, Capturefab refuses to write under its unmounted mount point. Destination removal does not remove files. destination remove NAME --forget-secret also removes its keychain secret.

Monitor and recover uploads

Capturefab saves bucket and server captures locally, then adds them to a persistent upload queue. Failed uploads keep their local files. You can retry them.

The destination selector shows pending or failed uploads and a Retry action. Keep a GUI or serve session active to upload queued files. Only one process holds the uploader lock at a time. Storage retention cannot delete a queued file before its upload succeeds.

capturefab uploads --json
capturefab uploads retry
capturefab uploads retry UPLOAD_ID
capturefab uploads wait --timeout 10m --json
# Remove a failed queue entry while keeping its local file
capturefab uploads forget UPLOAD_ID

Status lists pending, uploading and failed entries, upload errors, uploaded totals and uploader activity. Temporary-worker captures wait for remote uploads and include uploads in the result. Use --direct --camera ID to select this mode. A persistent session returns local capture results with queued_uploads. Examine the queue to confirm remote completion. recent_completed lists the last 20 uploads with their SHA-256.

If an upload fails, do a destination test. Examine the bucket, server, folder, host key and credentials. Then retry the upload. Capturefab does not overwrite remote files; use a new output name if the key exists. Use --keep-local to keep local files after successful uploads.

Capture & save

Set storage budgets and retention

Capturefab tracks its output files across folders and processes. The initial shared storage limit is 10 GiB and 10,000 files.

Open Storage & retention in Capture, or in Video while Record to file is selected. Its closed summary shows the current budget. Use up to and Keep at most limit Capturefab output. When full selects whether Capturefab stops or deletes the oldest eligible files. With deletion enabled, Delete captures older than a set age and Older than add an age limit. An app-wide policy can be stricter.

capturefab storage --json
capturefab storage configure --max-space 2GiB --max-files 1000 --on-full stop
capturefab --camera sim:0 capture -n 100 -o frames --max-space 1GiB

# Explicitly allow deletion of verified Capturefab-owned files
capturefab --camera sim:0 capture --interval 1m -n 10000 -o history \
  --max-space 1GiB --delete-oldest --max-age 7d
# Remove a saved age limit
capturefab storage configure --no-max-age

storage configure saves the global policy for subsequent runs. Per-command limits can reduce its limit. Active recording reservations use the same budget. Each video file also has a maximum size, which defaults to 512 MiB. The budget covers Capturefab captures and recordings. It does not cover unrelated disk files.

The default stop policy reports storage_full, with exit code 6. --delete-oldest permits deletion of completed Capturefab files only if their identity and SHA-256 still match. Retention protects user files, modified captures, replacements and active recordings. Capturefab applies age retention when it allocates new captures. Queued uploads stay protected until upload succeeds.

Processes of one user share the storage ledger and budget in the state directory, which survives reboots. A different CAPTUREFAB_SESSION_DIR uses a separate ledger. If a tracked file is missing, Capturefab releases its recorded usage. After a crash, the operating system releases locks so Capturefab can reconcile interrupted reservations.

Save camera setup, capture, schedule and recording commands in one JSON file. Review the plan before you apply it to a session.

Save this example as workflow.json. Each step contains a session command. An outer camera field can select the target camera. The connect and select operations specify the camera inside command.

{
  "version": 1,
  "steps": [
    {"command": {"op": "connect", "camera": "sim:0", "timeout_ms": 2000}},

Troubleshooting

Read the full Activity error. Examine the source and available build capabilities before you change settings.

capturefab doctor --json
capturefab ffmpeg --json
capturefab discover --json
capturefab sessions --json
capturefab --session bench status --json
A small computer is slow or warns when a session starts

Run doctor without --json. It checks this computer, for example where session state lives, the GigE receive buffer and the storage budget against free disk space, and prints a fix under each warning. serve prints the same warnings on one line when it starts. Efficient mode decodes each live stream with one thread, uses a faster libx264 preset and lets automatic capture embed frames on the CPU with a fifth of a core instead of half; in the desktop app it also draws at most 15 preview frames a second, 5 per overview tile, at most 1280 pixels a side, and skips animations. Captures and recordings keep every frame. Set it with --efficiency efficient, CAPTUREFAB_EFFICIENCY or the desktop app's Settings › Performance. When the app shows Preview 9 of 30 fps, this computer draws fewer frames than the camera sends; that button turns on Efficient preview.

An SSH shell cannot find a session a service started

Without XDG_RUNTIME_DIR, a service uses /run/user/<uid>, where logins look too, but only when its user lingers, because logind otherwise removes that directory at logout. Run doctor as the service user. If it warns about runtime_dir, run sudo loginctl enable-linger for that user and give the unit Wants= and After=user@<uid>.service. Settings, destinations, the upload queue and the storage ledger stay in the state directory either way.

doctor says state an older version left is no longer read

On Linux, settings, destinations, the upload queue and the storage ledger move once from the folder an older version kept them in to the state directory. When the state directory already has its own copy, or two old folders hold one, as when a service and a login both used Capturefab, nothing is replaced and the old_state check names the folder. To keep the old copy, stop Capturefab and move its files into the state directory in place of the ones there; otherwise delete them.

A camera is missing or cannot connect

Read the discovery warnings. Try the camera’s full discovered ID. For GigE, examine the network interfaces in doctor --json and camera reachability on its subnet. For USB3 Vision, examine operating system access and the necessary interface driver. For webcams, give camera permission and use the ID from native. If the app has the camera open, use its session.

Acquisition times out or loses GigE packets

Make sure that the camera streams and its trigger configuration can supply frames. For a slow source, increase --timeout-ms within the 60,000 ms limit. Examine packet size, receive buffer, resend and loss counters in transport status. GigE supports limited packet resend when the camera advertises it. Stop acquisition before you change locked format or geometry features.

A feature is locked or a setting is rejected

Examine current access, limits, increments and choices in Features. Select Stop beside Locked while streaming. Apply the value again. A read-only source stays read-only after a stop. Native VideoMode choices depend on the driver. Read back important values after a write.

A frame’s pixel format is unsupported

Image conversion supports Mono8, unpacked Mono10/12/16, RGB/BGR8 and Bayer8. Unsupported packed, chunk, multipart or GenDC formats produce errors. Stop acquisition before you select a supported, available PixelFormat. Use --format raw to keep acquired bytes when necessary. The area-scan simulator provides Mono8, RGB8, Mono12 and BayerRG8.

A stream, video file or encoder fails

Use ffmpeg --json to see the build’s protocols and encoders. Make sure that the receiving server is active and its address is reachable. Try encoder auto. Hardware encoding is available only with suitable host drivers and a successful encoder trial. For a development build, it can be necessary to set CAPTUREFAB_FFMPEG=/absolute/path/to/ffmpeg. Release builds include their FFmpeg executable.

The preview has a graphics problem

The app uses wgpu for graphics and can use software rendering if necessary. Start with ICED_BACKEND=tiny-skia to force software rendering. CAPTUREFAB_GPU_PREVIEW=0 keeps the GPU renderer but converts camera frames on the CPU. Use CAPTUREFAB_APPEARANCE=light or dark to set the appearance.

Capture stops with storage_full or an absent drive

Run storage --json to see the shared budget and reservations. Release disk space or select another output. Increase the budget only if you intend to permit more disk use. An absent external drive produces unavailable. Failed uploads keep their local files protected from retention. If an output filename exists, use a {seq} template or --on-exists number.

A signal source does not connect or shows no values

Use signals read URI to test the address and tags. Exit code 3 means that the device refused the connection. Exit code 4 means that it did not reply in time. Exit code 5 means that this build does not include the protocol; examine signals in doctor --json. For Modbus, examine the unit ID, table and 0-based address. For OPC UA, use signals browse to find node IDs.

A dataset is locked or an export fails

A running session keeps its dataset open. Use --session NAME for dataset query and dataset export, or close the dataset first. An export folder must be new. If an export fails with storage_full, release disk space or increase the storage budget.

A scanner does not respond or rejects a setting

Examine scanner runtime availability in doctor --json. Make sure that the necessary operating system driver is installed. Use the full scanner: ID and a 60-second timeout. If the driver uses another source name, set ScanSource=Default. Drivers can support only some of the available settings. Scanner sources do not support auto exposure or forwarding.

Include the app version, operating system, source type and exact command in a bug report. Add relevant doctor output and the Activity error. Remove private data from logs before you share them through GitHub Issues.

Reference

Build, architecture and licensing

One Rust executable provides the native desktop app and CLI. Each connected camera has a separate worker process and a limited shared-memory frame ring.

Desktop, direct CLI and session clients send the same commands to a coordinator. Each camera worker owns its transport, current feature map, capture schedules and forwarder. Commands use limited JSON control channels. Frames use a three-slot shared-memory ring that gives priority to the newest frame. FFmpeg processes media and encodes video in a separate executable process. Each signal source runs in its own helper process. The coordinator owns the dataset file.

Capturefab implements GigE Vision, USB3 Vision and GenICam in Rust. This initial implementation does not provide all Aravis or vendor SDK features. Camera behavior and support can change between releases.

Build from source

Install a stable Rust toolchain, a C compiler and CMake. On x86, install NASM for libjpeg-turbo SIMD. These tools are necessary only for development. A development build can use CAPTUREFAB_FFMPEG. Release builds include the configured FFmpeg binary and its notices.

git clone https://github.com/capturefab/capturefab
cd capturefab
cargo build --release
# Headless release set: cameras, scanners, images, signals and exports
cargo build --release --no-default-features \
  --features usb,scanner,jpeg,nvjpeg,vaapi,videotoolbox,parquet,modbus,mqtt,opcua,mtconnect
target/release/capturefab --camera sim:0 capture -o first.png
cargo test

Licensing and release provenance

Capturefab uses the MIT license. Release binaries include a separately executed GPLv3 FFmpeg build. FFmpeg includes x264, SRT and OpenSSL with their own licenses. Capturefab does not link FFmpeg into its executable. The release license output lists the linked Rust crates. The MPL-2.0 async-opcua crates include a link to their source. Redistribution must include FFmpeg’s complete corresponding source, build scripts and notices.

See the FFmpeg build and compliance guide for source, build and license details. The release process explains release verification. The release manifest lists available files, checksums and build metadata. Source and license notices accompany release builds.
