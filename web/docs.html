Start here

Your first capture

Open a camera, inspect a frame and save an image. The built-in pattern camera lets you follow along before connecting hardware.

  1. Download the desktop build for your operating system and processor, verify its checksum, then open capturefab.
  2. Enable Include simulated cameras in the sidebar and choose a Pattern camera, or enter sim:0 as the camera address. Connect it and start its stream.
  3. Select the camera. Open Features to inspect its settings; open Capture to save a frame.
  4. Set an Output path such as first.png, leave Frames at 1 and Format at PNG, then choose Capture & save.

Capture acquires a frame even when the preview is stopped. The path shown below the save button confirms where the file went. Existing files are never overwritten: choose a new name for each attempt.

# The same first capture from a terminal
capturefab --camera sim:0 capture -o first.png

# Inspect the simulator, then capture a sequence
capturefab --camera sim:0 features
capturefab --camera sim:0 capture -n 10 -o first-frames

Screenshots show the current development app with simulator sources. Controls can differ by release.

Install and verify a release

Choose a desktop build for the app and CLI, or a headless build for machines without a display. Match the installed operating system’s architecture.

The download page lists published artifacts and their SHA-256 checksums. An empty release manifest means a release has not been published. Apple silicon uses ARM64; Intel and AMD PCs usually use x64. On Raspberry Pi and Jetson, match the installed OS: a 64-bit processor may run a 32-bit system.

Verify the downloaded file
SystemCommand
Linuxsha256sum DOWNLOADED_FILE
macOSshasum -a 256 DOWNLOADED_FILE
Windows PowerShellGet-FileHash DOWNLOADED_FILE -Algorithm SHA256

Compare the result with the checksum for that exact asset. On Linux or macOS, make a downloaded standalone executable runnable with chmod +x ./capturefab, then launch ./capturefab. Put it on your PATH to use the shorter commands in these guides.

Release binaries bundle a separate FFmpeg executable. A separately installed Aravis, FFmpeg, libusb, vendor SDK or Python is not required. Operating system graphics and camera drivers are still required; document scanners have platform driver requirements.

capturefab --version
capturefab doctor --json
# Optional: verify GitHub build provenance
gh attestation verify DOWNLOADED_FILE --repo capturefab/capturefab

For a source build, see Build, architecture & licensing.

Understand the workspace

The camera list, preview and inspector keep connection, image and settings in view. Select a camera to make its controls active.

Camera list
Find discovered, connected and recently used sources. Enter an IP address, stream URL or video file to connect directly.
Preview stage
See connected cameras together, then open one camera for a larger view. Streaming state, frame rate and errors belong to each camera.
Inspector
Features edits camera settings, Capture saves images and schedules, and Forward records video or publishes a stream.
Activity
Read commands, warnings and errors for the selected camera, including commands sent from another terminal.

Press Enter to open the selected camera and Esc to return to all cameras when no input field has focus. Use the bottom toolbar to show or hide the camera list, settings and Activity. Keyboard shortcuts cover these actions.

The app follows your system’s light or dark appearance and remembers workspace settings and recent camera addresses. Addresses containing credentials or secret query parameters are not saved. You can override appearance at launch with CAPTUREFAB_APPEARANCE=light or dark.

Connect & inspect

Find and connect cameras

Discovery lists network, USB3 Vision, host-driver and ONVIF cameras, plus platform scanners. Connect a result or enter a source directly.

  1. Run discovery from the camera list. Check any discovery warning before assuming a missing device is unavailable.
  2. Choose the camera to connect. Select its tile or list entry to inspect it.
  3. Start streaming for a continuous preview. Stop acquisition before changing a camera’s geometry or native video mode.
capturefab discover --json
capturefab native --json           # webcams and capture cards
capturefab onvif discover --json   # ONVIF devices on the LAN
capturefab scanners --json
capturefab --simulate discover    # include the pattern camera

# Reuse an open desktop session
capturefab sessions
capturefab --session gui connect sim:0
capturefab --session gui start

Camera selectors accept a discovered ID, unique serial or GigE IPv4 address. A GigE camera needs a reachable address on the camera’s subnet. USB3 Vision needs userspace access: USB permissions on Linux, an available IOKit interface on macOS and WinUSB on Windows. Native webcams may require the OS camera permission.

Use --session NAME when the camera is already connected in the app; opening a second connection can fail because camera control is often exclusive. --camera ID targets a connected camera without changing the visible selection. select ID changes the inspector selection; disconnect releases the addressed camera.

Camera and media source locators

A source locator tells Capturefab which camera, stream or file to open. Quote locators containing spaces or URL query parameters.

Choose a native camera mode

Native locators accept ?size=1280x720&fps=30. Inspect Features for advertised VideoMode choices or set supported Width, Height and AcquisitionFrameRate before starting acquisition. Actual modes depend on the driver; V4L2 format listings do not establish frame-rate bounds.

capturefab --camera 'avfoundation:0?size=1280x720&fps=30' capture -o webcam.png
capturefab --camera 'rtsp://camera/live' capture -o network.png
capturefab --camera '/path/to/clip.mp4' capture -o video-frame.png
capturefab onvif resolve 'http://camera/onvif/device_service' --username admin --json

For ONVIF, supply the password through CAPTUREFAB_CAMERA_PASSWORD. Authenticated locators also use onvif://USER:PASS@HOST/onvif/device_service; percent-encode reserved characters. UI and status redact credentials, but your shell may still record typed secrets. HTTPS SOAP and Media2-only devices are currently unsupported.

HDMI capture devices appear through their host video driver. CSI cameras need an accessible supported OS video device; libcamera-only pipelines and proprietary tethering protocols are not implemented. capturefab compatibility MODEL provides connection guidance; it does not certify a camera.

Connect & inspect

Scan documents

Scanners use the same capture, preview, destination, schedule and storage tools. Each capture requests one page.

Discover a scanner, connect its full ID and choose Scan resolution, Scan mode and Scan source in Features. Open Capture and choose Scan & save. Connecting or starting acquisition does not scan a page.

Scanner controls
FeatureValuesDefault
ScanResolution75–600 dpi150
ScanModeColor, Gray, LineartColor
ScanSourceDefault, Flatbed, FeederDefault, leaving the driver’s source unchanged
capturefab scanners --json
# Replace DEVICE with the full returned scanner ID
capturefab --camera 'scanner:sane:DEVICE' --timeout-ms 60000 capture \
  --set ScanResolution=300 --set ScanMode=Gray --set ScanSource=Feeder \
  -n 5 -o pages

Linux uses installed SANE scanimage and backends; CAPTUREFAB_SCANIMAGE can select its path. Windows uses a WIA driver through Windows PowerShell. macOS uses a bundled ImageCaptureCore helper and a compatible driver. Drivers may reject settings they do not support; Capturefab does not silently substitute another mode. Use Default for a SANE driver with source names other than Flatbed or Automatic Document Feeder.

The GUI’s scanner timeout starts at 60 seconds; use --timeout-ms 60000 for CLI scans. A timeout, stop or disconnect terminates acquisition. Multi-page captures save separate images, not one PDF. Samples normalize to 8-bit RGB or grayscale with a 128 MiB page limit. PDF assembly, OCR, forwarding and camera auto exposure are not provided. Physical scanner compatibility has not been validated.

Connect & inspect

Inspect and change camera features

The Features panel reads the camera’s live feature map, including current values, access, choices, bounds and units.

  1. Select a connected camera and open Features. Search by feature name, display label or description.
  2. For a numeric or text field, edit the value and press Enter or choose Apply. Choice menus and checkboxes apply their changes directly.
  3. Read back the accepted value. A camera may round a value to its supported increment. A rejected write displays its reason at the field.

Features are grouped into Image, Acquisition, Device, Transport and Other. Exact names and availability depend on the source. Hover a label for its underlying feature name and description. The Locked while streaming banner offers Stop for settings that acquisition currently locks.

capturefab --camera sim:0 features --filter Exposure
capturefab --camera sim:0 get Width Height PixelFormat ExposureTime
capturefab --camera sim:0 set ExposureTime=5000 Gain=0
# A camera command, when the device exposes it
capturefab --session bench execute TriggerSoftware

CLI assignments run in the given order; a later failure does not roll back earlier successful writes. Inspect features first and read back important settings. A manual edit to a feature managed by Auto switches that camera to manual. Reversible acknowledged settings can use Undo and Redo.

Connect & inspect

Tune auto exposure and frame rate

Enable Auto for one camera, then choose the balance between image quality and frame rate. Cameras start in manual mode.

In Features, use the Exposure card to switch from Manual to Auto. Move the slider toward Quality for longer exposure with less gain, or toward Frame rate for shorter exposure with more gain. The midpoint is the initial balance, 0.5.

Auto prefers the camera’s own automatic exposure, gain and white balance controls; otherwise Capturefab adjusts exposure and gain. It may raise frame-rate or GigE throughput limits when the link has headroom, then backs off on packet loss. Expand Auto changes to see changes and their reasons. Stable and Limited are settled states; Waiting means acquisition is stopped.

capturefab --session bench auto --balance quality
capturefab --session bench auto --balance 0.5
capturefab --session bench status --json
capturefab --session bench manual
capturefab --session bench manual --revert

capturefab --camera sim:0 capture --auto --balance 0.25 -o tuned.png

manual disables camera auto functions and holds their current values. manual --revert restores the settings Auto changed. Disconnecting, ending a direct command or closing the session also restores those settings where possible. In a persistent session, capture --auto leaves Auto enabled after the capture.

For capture --auto, repeated --set assignments apply first. Capture waits briefly for exposure to settle, bounded by half the transport timeout and at most 3 seconds; it can still save before settling. Inspect result.auto.state in JSON when that matters.

Connect & inspect

Preview, zoom and compare cameras

Keep the overview for multiple live cameras, or open one camera to inspect its image at a useful scale.

Connect more than one source to show a grid. Selecting a camera changes the inspector; opening it gives the preview more room. Press Esc outside a field to return to the grid. Each camera acquires independently, so selecting another camera does not stop its stream.

  • Fit centers the entire frame in the available area. Use ⌘0 on macOS or Ctrl+0 elsewhere.
  • Actual pixels shows the image at 1:1 with ⌥⌘0 or Ctrl+Alt+0.
  • Zoom in / out uses ⌘+ / ⌘− or Ctrl+= / Ctrl+−.
  • Image only hides workspace panels. Press F when no field has focus, then press it again to return.

The live preview favors the latest frame instead of building a queue when rendering falls behind. Preview scale changes the display, not the capture’s saved resolution. The default session supports 16 connected cameras; CAPTUREFAB_MAX_CAMERAS accepts 1–64.

If the preview fails, open the camera’s Activity details. Troubleshooting covers frame timeouts, graphics fallback and transport diagnostics.

Connect & inspect

Read the histogram and focus scores

Check clipped shadows and highlights, then use a movable focus region to compare sharpness while adjusting the lens.

Histogram

Press H outside an input field to show the Histogram. It displays Mean intensity, Shadows crushed to black and Highlights with a blown-out channel. Use it alongside Exposure and Gain; the histogram itself does not change camera settings.

Focus region

  1. Press R outside a field to show the focus region and score.
  2. Move and resize the region over useful detail in the image.
  3. Choose a metric and adjust the lens to raise the score. Compare the trend and % of peak under similar lighting and scene content.
  4. Use Reset peak after changing the scene or starting a new adjustment.
Focus metrics
MetricWhat it measures
LaplacianVariance of the Laplacian; responds to fine edges.
TenengradSquared Sobel gradient; useful on strong edges and in noise.
BrennerSquared differences two pixels apart; favors fine texture.
VarianceNormalized intensity variance; a contrast measure, gentle on noise.

The score is a relative image measurement, not a lens calibration or autofocus command. A change in subject, lighting, gain or region can change it independently of focus.

Capture & save

Capture images and sequences

Save one complete frame to a file, multiple frames to a directory, or a named sequence using a frame template.

  1. Open Capture for the selected camera.
  2. Choose Save to and enter an Output path. Set Frames, Format and Timeout.
  3. Choose Capture & save. Check the saved path or error below the button.
capturefab --camera sim:0 capture -o frame.png
capturefab --camera sim:0 capture -n 10 -o frames
capturefab --camera sim:0 capture -n 10 -o 'run-{frame}.png'
capturefab --camera sim:0 capture --format jpeg -o frame.jpg
capturefab --camera sim:0 capture --set Width=640 --set Height=480 -o configured.png

# One binary image to stdout; do not combine with --json
capturefab --camera sim:0 capture -o - --format ppm > frame.ppm
Image formats
FormatUse
pngDefault lossless image output.
jpeg / jpgSmaller lossy stills, quality 90; requires the JPEG build feature.
rawPreserve frame bytes when image conversion is unsupported or unnecessary.
pgmPortable grayscale output.
ppmPortable RGB output.

--timeout-ms is the per-frame transport deadline, initially 2,000 ms, from 1 to 60,000 ms. --count accepts 1–100,000 frames. Capture never silently replaces an existing output file; use a new name, directory or template. For delayed and repeated captures, see Scheduled captures.

Capture & save

Schedule captures and timelapses

Start later or capture at intervals. Each running session exposes job progress, the next frame time and cancellation.

  1. In Capture, set the output, frame count and format.
  2. Enable Capture on a schedule. Enter Start after and Frame interval in seconds.
  3. Choose Schedule capture. The Scheduled jobs section shows progress and a Stop button for pending or running work.
# Direct commands wait for their job to finish
capturefab --camera sim:0 capture --delay 30s -o later.png
capturefab --camera sim:0 capture --interval 10s -n 360 -o timelapse

# Existing sessions return a job ID
capturefab --session bench capture --delay 5s --interval 1m -n 60 -o timed-frames
capturefab --session bench jobs --json
capturefab --session bench cancel 1

# Use a future timestamp with an explicit timezone
capturefab --session bench capture --at 2026-12-01T09:00:00-05:00 \
  --interval 1m -n 100 -o morning

--at and --delay are alternatives. Durations accept ms, s, m, h, d, or plain seconds. The frame count bounds a timelapse. Every acquisition still has a bounded transport timeout.

Durations and timestamp fractions must resolve to whole milliseconds: 1.001s is valid; 1.1ms is rejected instead of rounded. All scheduled frames must fall within 10 years. A past timestamp starts immediately; a zero RPC interval captures consecutive frames. Active jobs on one camera cannot target the same future output file.

Keep the GUI, headless session or direct command running: schedules do not survive process exit. Stopping acquisition with stop cancels pending capture jobs on that camera. A stopped or failed job remains visible with its progress and error.

Capture & save

Save to folders, external drives and S3

Save a named destination once, then reuse it for images, schedules and local video recordings.

  1. Open Manage… beside Save to in Capture or Forward.
  2. Choose Add folder… for a local, external or network folder, or Add S3 bucket… for S3-compatible storage.
  3. Enter a name and destination details. Use Test to check access, then Save.
  4. Select the saved destination in Save to. Enter the file, folder or {frame} template relative to that destination.
capturefab volumes --json
capturefab destination add-folder archive '/path/to/captures'
capturefab destination list --json
capturefab destination test archive
capturefab --camera sim:0 capture --destination archive -o run-1 -n 10

# Use an existing AWS profile; no secret in the command
capturefab destination add-s3 cloud --bucket YOUR_BUCKET \
  --region us-east-1 --prefix captures/ --profile YOUR_PROFILE
capturefab --camera sim:0 capture --destination cloud -o frame.png

Bucket credentials and providers

Choose an access key kept in the OS keychain, an AWS shared-credentials profile, or environment credentials from the uploading process. Destination settings contain no secret keys. The CLI accepts --access-key-id with --secret-stdin to read the secret from stdin; keep secrets out of command lines.

For non-AWS services, set the service --endpoint, correct --region and, when required, --path-style. A --prefix adds a bucket key prefix. --keep-local retains local copies after verified upload. S3 operations require a build with the s3 feature.

Mounted drives appear as shortcuts in the picker. If an external drive is absent, Capturefab refuses to write beneath its unmounted mount point. Removing a destination does not remove its files. destination remove NAME --forget-secret also removes its saved keychain secret.

Capture & save

Monitor and recover uploads

Bucket captures finish locally before entering a persistent upload queue. Failed uploads retain their local files and can be retried.

The destination picker shows waiting or failed uploads and a Retry action. Keep a GUI or serve session running to drain the queue. One process at a time holds the uploader lock. A queued file is protected from storage retention until its upload succeeds.

capturefab uploads --json
capturefab uploads retry
capturefab uploads retry UPLOAD_ID
capturefab uploads wait --timeout 10m --json
# Remove a failed queue entry while keeping its local file
capturefab uploads forget UPLOAD_ID

Status reports pending, uploading, failed entries with their errors, uploaded totals and whether an uploader is running. Direct --camera captures to a bucket wait for their uploads and include uploads in the result. A persistent session returns local capture results with queued_uploads; inspect the queue for remote completion.

If uploading fails, test the destination, check its bucket, endpoint, region and credentials, then retry. Existing remote objects are not overwritten; a key collision must be resolved with a new output name. Use --keep-local on a bucket destination when completed uploads should leave a local archive.

Capture & save

Set storage budgets and retention

Capturefab tracks the files it owns across output folders and processes. The initial shared ceiling is 10 GiB and 10,000 files.

Open Storage & retention in Capture or Forward. Disk budget and File limit bound owned output. At capacity chooses stopping or deleting the oldest eligible files. Limit capture age and Keep for add age retention when deletion is enabled.

capturefab storage --json
capturefab storage configure --max-space 2GiB --max-files 1000 --on-full stop
capturefab --camera sim:0 capture -n 100 -o frames --max-space 1GiB

# Explicitly allow deletion of verified Capturefab-owned files
capturefab --camera sim:0 capture --interval 1m -n 10000 -o history \
  --max-space 1GiB --delete-oldest --max-age 7d
# Remove a saved age limit
capturefab storage configure --no-max-age

storage configure persists the global policy across restarts; per-command limits can lower its ceiling. Active recording reservations count toward the same budget. A video file also has a separate maximum size, initially 512 MiB. The budget covers Capturefab capture and recording data, not unrelated files on the disk.

The default stop policy reports storage_full, exit code 6. Deletion is explicit: --delete-oldest only removes completed owned files whose identity and SHA-256 still match. User files, modified captures, replacements and active recordings are protected. Age retention runs when allocating new captures. Queued uploads are held back from retention.

Processes sharing CAPTUREFAB_SESSION_DIR share the ledger and budget. Changing that directory creates a separate ledger. Missing owned files release their recorded usage; crash-released OS locks allow interrupted reservations to be reconciled.

Capture & save

Find saved paths and inspect Activity

Confirm the latest saved output under the capture button and use Activity for the command history and full error details.

After a successful capture, the line below Capture & save shows the saved filename or sequence folder and the named destination, when used. Hover for the path or use its copy button. For scheduled output, check the job’s path and frame count in Scheduled jobs.

Open Activity from the bottom toolbar, or press ⌘J / Ctrl+J. Events show command results, warnings and errors for the selected camera. Error notices offer Details; an error on another camera’s tile can select that camera and open its full Activity message.

Use Copy log to include the actual error in a bug report. Commands sent through a CLI session appear in the same app log, so you can see what automation changed. The Activity log is session feedback; the storage ledger tracks owned files and usage.

capturefab --session bench status --json
capturefab --session bench jobs --json
capturefab storage --json
capturefab uploads --json

Capture & save

Undo and redo changes

Undo edits in the desktop and acknowledged reversible camera changes. Each connected camera shares its change history with session clients.

Use the bottom toolbar’s Undo and Redo controls, ⌘Z / ⇧⌘Z on macOS, or Ctrl+Z / Ctrl+Shift+Z elsewhere. Ctrl+Y also redoes outside macOS. Continuous edits are grouped into one change; a new change clears redo.

capturefab --session bench --camera sim:0 history --json
capturefab --session bench --camera sim:0 undo --json
capturefab --session bench --camera sim:0 redo --json

Camera history covers reversible feature writes, auto/manual and streaming changes. status.history and cameras[].history expose the next undo/redo labels, or null. History is bounded and lasts for the camera connection. Replay checks the camera state; a conflict or failed replay keeps the entry for inspection.

Capture files, uploads, recording, schedules, connection changes, arbitrary camera commands and raw memory writes have external effects that camera history cannot reverse. Stopping a stream with schedules or forwarding is also excluded. Inspect the next label before undoing a change made by another session client.

Record & automate

Record bounded video files

The Forward panel also records to a local video file. A shared storage budget and per-file size limit bound its output.

  1. Open Forward and choose Save to.
  2. Enter a recording filename such as clip.mkv in Stream URL or file.
  3. Choose Codec, Encoder, Frame rate, Bitrate and Maximum file.
  4. Choose Start forwarding. Stop forwarding to finish the file.
# record is an alias of forward
capturefab --camera sim:0 record -o clip.mkv --duration 30s \
  --codec h264 --encoder auto --fps 30 --bitrate 4M --max-file-size 512MiB

# A persistent session records until stopped
capturefab --session bench record -o clip.mp4 --destination archive
capturefab --session bench stop-forward

Local .mkv, fragmented .mp4 / .mov, .ts and suitable .webm files use a bounded writer. Select a codec that the container accepts. --duration limits a direct command; with --session, recording continues until stop-forward. The default codec is H.264, frame rate 30 fps, bitrate 4M, and maximum file size 512 MiB.

Encoder auto probes usable hardware before falling back to software. Enter an FFmpeg encoder name to choose explicitly. Use doctor and ffmpeg to inspect this machine and build. A saved S3 destination queues the finished recording for upload.

Record & automate

Forward a stream to a recorder

Publish frames to an existing RTSP, SRT, RTMP, UDP or HTTP destination. The receiver or recording server must already be running.

In Forward, enter the receiving endpoint in Stream URL or file. Set the codec, encoder, rate and bitrate, then choose Start forwarding. The active forward card shows its destination and a stop control; changing the form does not alter an already running forward.

capturefab --camera sim:0 forward \
  --output rtsp://localhost:8554/camera \
  --encoder auto --fps 30 --bitrate 4M --duration 60s

capturefab --session bench forward --output rtsp://localhost:8554/camera
capturefab --session bench stop-forward
capturefab doctor --json
capturefab ffmpeg --json

Frames use a bounded latest-frame queue. Encoder availability comes from a real probe of the build and host drivers; GPU branding alone does not establish support. --encoder chooses encoding, while the global --hwaccel option controls FFmpeg input decoding.

Protocol and codec support depend on the bundled FFmpeg configuration. Local HLS output is not implemented; a server such as MediaMTX can serve HLS from the stream you publish. Scanner sources do not forward.

Record & automate

Control the app from a script or headless session

Attach CLI commands to the camera connection already open in the desktop. Use serve for the same persistent interface without a window.

Run sessions first to find the existing session name. The ordinary desktop defaults to gui; an explicitly named window or headless session may use another name. The Capture panel’s Automation section and the Quick guide can copy a command for the visible session.

capturefab gui --name bench
# In another terminal:
capturefab sessions --json
capturefab --session bench connect sim:0
capturefab --session bench connect sim:1
capturefab --session bench --camera sim:0 set ExposureTime=2500
capturefab --session bench --camera sim:1 capture -o second.png
capturefab --session bench status --json

# An alternative to the desktop, kept running in the foreground
capturefab --camera sim:0 serve --name headless --stream

--camera ID targets one connected camera without changing visible selection. select ID changes that selection. connect ID, disconnect, start and stop manage a persistent camera. Set CAPTUREFAB_SESSION to avoid repeating --session.

Send session JSON directly

capturefab schema --json
printf '%s\n' '{"op":"get","feature":"Width"}' | capturefab --session bench rpc --json

The session server uses loopback TCP and a private local token. The descriptor and token live in the private session directory; this is a local automation interface. GUI commands and CLI/RPC clients share camera state, history and Activity. Direct --camera commands without --session create a temporary connection for that command.

See the agent instructions and llms.txt for automation guidance. The installed binary’s schema and --help are authoritative for its version.

JSON results and exit codes

Supplied arguments are validated before connection and before capture/forward --set or --auto changes. RPC rejects unknown fields and invalid values with a description of the rejected input. Live camera, destination, storage and I/O failures retain their operation categories. Rejected writes to auto-managed features leave auto mode enabled.

Capture paths support only {frame}; use forward for network outputs. Retention --max-age needs whole seconds, at least 1s, with delete-oldest. Recording reservations must fit the requested budget; oversized --max-file-size values are rejected. --duration applies to direct forwarding; sessions use stop-forward.

Success and error envelopes go to stdout; diagnostics go to stderr. Check the exit code before consuming the result. Field order is not significant. Binary image stdout with capture -o -, raw XML output, native completions and normal help/version output follow their own Unix conventions.

{"version":1,"ok":true,"result":{}}
{"version":1,"ok":false,"error":{"code":"unavailable","message":"…"}}

Advanced camera diagnostics

xml -o camera.xml saves the camera’s GenICam XML. memory read ADDRESS LENGTH accepts decimal or 0x addresses, with lengths up to 65,536 bytes. memory write ADDRESS HEX_BYTES writes raw register bytes and is not undoable; use named features for routine configuration.

Troubleshooting

Start with the complete Activity error, then inspect the source and compiled capabilities before changing settings.

capturefab doctor --json
capturefab ffmpeg --json
capturefab discover --json
capturefab sessions --json
capturefab --session bench status --json
A camera is missing or cannot connect

Read discovery warnings and try its exact discovered ID. For GigE, check that the camera is reachable on its subnet and inspect the network interfaces in doctor. For USB3 Vision, check OS access and the required interface driver. For webcams, grant camera permission and use the ID from native. If the app already holds the camera, use its session instead of opening another connection.

Acquisition times out or loses GigE packets

Check that the camera is streaming and its trigger configuration can produce frames. Increase --timeout-ms for a slow source, within the 60,000 ms limit. Inspect transport status for packet size, receive buffer, resend and loss counters. GigE implements bounded packet resend when advertised by the camera. Stop acquisition before changing stream-locked format or geometry features.

A feature is locked or a setting is rejected

Inspect live access, bounds, increments and choices in Features. Choose Stop beside Locked while streaming, then apply the value again. A truly read-only source does not become writable by stopping. Native VideoMode choices are driver-specific. Read back important values after a write; a rejected field keeps the camera’s reason.

A frame’s pixel format is unsupported

Image conversion handles Mono8, unpacked Mono10/12/16, RGB/BGR8 and Bayer8. Unsupported packed, chunk, multipart or GenDC formats fail explicitly. Select an advertised supported PixelFormat while stopped, or use --format raw to preserve bytes when appropriate. The simulator offers Mono8, RGB8, Mono12 and BayerRG8.

A stream, video file or encoder fails

Check ffmpeg --json for this build’s protocols and encoders. Verify the receiving server is running and the endpoint is reachable. Try encoder auto; hardware encoding requires a successful real probe and host drivers. A development build may need CAPTUREFAB_FFMPEG=/absolute/path/to/ffmpeg. Release builds bundle their FFmpeg executable.

The preview has a graphics problem

The app renders with wgpu and can fall back to software. Start with ICED_BACKEND=tiny-skia to force software rendering. CAPTUREFAB_GPU_PREVIEW=0 keeps the GPU renderer but converts camera frames on the CPU. Use CAPTUREFAB_APPEARANCE=light or dark to override appearance.

Capture stops with storage_full or an absent drive

Run storage --json to see the shared budget and reservations. Free space or select another output; change the budget only intentionally. A missing external drive returns unavailable rather than writing into an empty mount directory. Inspect failed uploads as they keep local files protected from retention. Existing output names cause errors; use a new filename.

A scanner does not respond or rejects a setting

Check scanner runtime availability in doctor and the required host driver. Use the full scanner: ID and a 60-second timeout. Set ScanSource=Default if the driver uses another source name. Scanner drivers can support a subset of the offered settings. Auto exposure and forwarding are unsupported for scanner sources.

For a reproducible bug report, include the app version, OS, source type, exact command, relevant doctor output and Activity error. Review logs for private data before sharing them through GitHub Issues.

Build, architecture and licensing

One Rust executable provides the native desktop and CLI. Each connected camera owns a separate worker process and bounded shared-memory frame ring.

The desktop, direct CLI and session clients send the same commands to a coordinator. Every camera worker exclusively owns its transport, live feature map, capture schedules and forwarder. Commands use bounded JSON control channels; frames travel through a three-slot shared-memory ring with the newest frame preferred. FFmpeg handles media and encoding in a separate executable process.

GigE Vision, USB3 Vision and GenICam are native Rust implementations. This is an initial implementation under rapid development, not complete Aravis or vendor SDK feature parity. Camera behavior and support may change between releases.

Build from source

Install a stable Rust toolchain, a C compiler and CMake, plus NASM on x86 for libjpeg-turbo SIMD. Build tools are development dependencies. A development build can use CAPTUREFAB_FFMPEG; release builds embed the configured FFmpeg binary and matching notices.

git clone https://github.com/capturefab/capturefab
cd capturefab
cargo build --release
# Headless build with camera, scanner and image features
cargo build --release --no-default-features \
  --features usb,scanner,jpeg,nvjpeg,vaapi,videotoolbox
target/release/capturefab --camera sim:0 capture -o first.png
cargo test

Licensing and release provenance

Capturefab is MIT licensed. Release binaries bundle a separately executed GPLv3 FFmpeg payload, including x264, SRT and OpenSSL with their own licenses. FFmpeg is not linked into Capturefab. Redistribution of a bundled release must include FFmpeg’s complete corresponding source, build scripts and notices.

See the FFmpeg build and compliance guide, release process and release manifest for exact build metadata, checksums and available provenance. Source and licensing notices accompany published builds.
