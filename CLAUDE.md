# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Capturefab is an MIT-licensed Rust camera and industrial data capture command-line tool for people, scripts and AI agents: one `capturefab` executable that lists, configures, captures from and records cameras, with a versioned JSON contract (`--json`, typed exit codes, `capturefab schema`). It implements GigE Vision, USB3 Vision and GenICam natively in Rust; webcams, RTSP/SRT/ONVIF streams, files and video encoding go through a bundled FFmpeg executable (not linked). JPEG and PNG stills are encoded in process (libjpeg-turbo, png, and Apple's JPEG engine through VideoToolbox on macOS), or on Linux by NVIDIA's nvJPEG or a VA-API driver in a helper process. Aravis is used only as an external test reference. There is no GUI, browser client, in-app assistant or update check.

## Vendor and native dependencies

Linking vendor SDKs and native libraries (camera SDKs, platform media frameworks, libusb, Aravis, GPU libraries loaded at run time such as CUDA/nvJPEG and libva) is permitted when it fits the repo's structure:
- Gate each one behind an optional Cargo feature so the default and `--no-default-features` builds keep working without it, and so `doctor` can report whether it was compiled in.
- Keep it in the process that uses it: camera SDKs belong in the per-camera worker (`session::run_worker`), never in the CLI client or the session coordinator.
- Isolate it in a separate helper process, the way FFmpeg is run, when its license cannot be combined with Capturefab's MIT code in release binaries (for example GPL), when it can crash, hang or leak and would take the camera worker down with it, or when it would bloat or complicate every build. Talk to helpers over bounded stdio JSON for control, and pipes or shared memory for pixels. The GPU JPEG encoders (nvJPEG, VA-API) are such: they run in `capturefab __jpeg-helper`, which the camera worker starts and which maps the frames' shared memory (`jpeg/helper.rs`).
- Check the vendor's redistribution terms before bundling its runtime, and add its notices to the release license output.

FFmpeg stays a separate executable. Never enable nonfree FFmpeg components: the bundled build is GPL, so a nonfree build could not be redistributed.

Timing-sensitive tests route their budgets, fake-peer delays, `--for` windows and elapsed bounds through `tests/support/time.rs` (`src/test_time.rs` for unit tests); `CAPTUREFAB_TEST_TIME_SCALE` (1–50, CI sets 10; keep scaled `timeout_ms` within the product limit of 30000) stretches them uniformly, so ordering margins survive slow runners. Reproduce runner slowness on macOS with `CAPTUREFAB_TEST_TIME_SCALE=10 taskpolicy -b cargo test --test NAME`.

CI checks the build MSRV with Rust 1.89.0. Check it locally with `cargo check --all-features --all-targets` and `cargo check --no-default-features --all-targets` under that toolchain. The lint policy uses Clippy 1.99 or newer, including lint names older Clippy releases do not recognize. Keep the build MSRV separate from the lint toolchain, and verify the selected `rustc --version` and `cargo clippy --version` when switching toolchains.

**Agent build coordination.** Batch related implementation and test changes before starting Cargo. Use one designated builder and keep another agent reviewing or preparing the next source batch while verification runs. Reuse the workspace target directory for native builds; retain only the distinct caches required by other toolchains/platforms and one active Linux validation cache. Do not create per-agent target directories or run competing build matrices. Combine affected test targets in one Cargo build, then reuse those executables for focused filters or repetitions. After validation, remove task-owned obsolete build trees, SDK archives and stale incremental state; preserve current incremental caches, useful logs and unrelated user files. Never run broad Docker pruning or delete caches in use.

Use the simulator (`-c sim:0`, `sim:1`, `sim:line`, `sim:depth`, `sim:microscope`, `sim:thermal`, `sim:replay:PATH`) to exercise acquisition without hardware. Set `CAPTUREFAB_SESSION_DIR` and `CAPTUREFAB_CACHE_DIR` to isolated temp dirs when running the binary manually or in tests (tests set both for every binary they spawn; unit tests isolate themselves). The session dir must be private (mode 0700, as `mktemp -d` makes) or not exist yet: when its group or others have any access, commands that start a session (`--keep DUR`, `--background`, `serve`, `session start`) fail with `permission_denied` and a `chmod 700` hint; those that look for one find none (`session list` and `jobs` list nothing, `session status|stop` exit 3 `session_not_found`, with the `chmod 700` hint when given a name, as `--session NAME` is); and the warm default falls back to a worker of the command's own. Three directories, found lazily by `dirs.rs` (`dirs::runtime`, `state`, `cache`; `dirs::scratch` and `temp` for short-lived files) as the first candidate that is or can be made private (0700, owned, not a symlink) and writable, so read-only and immutable hosts fall back to their tmpfs: runtime holds session descriptors, locks and other files needed only while processes run (`CAPTUREFAB_SESSION_DIR`, else `$XDG_RUNTIME_DIR/capturefab`, else a lingering Linux login's `/run/user/<uid>/capturefab`, else `~/.cache/capturefab/sessions`, else `/run/capturefab-0` for root on Linux, else `$TMPDIR/capturefab-<uid>`); state holds presets (`setups/`), the saved sign-in index, sessions' jobs and background session logs (`sessions/NAME.log`) (`CAPTUREFAB_STATE_DIR`, else `CAPTUREFAB_SESSION_DIR`, else `$XDG_STATE_HOME/capturefab` or `~/.local/state/capturefab` on Linux, the runtime dir's default elsewhere, else none); cache holds the extracted FFmpeg, encoder probes and GenICam XML (`xml/`) (`CAPTUREFAB_CACHE_DIR`, else the platform cache, else `<runtime>/cache`). A variable is used as given, with no fallback. A missing folder degrades one feature at a time: no runtime dir means no sessions (commands open their cameras alone), no state dir makes presets and sign-ins fail with `permission_denied` naming `CAPTUREFAB_STATE_DIR`, no cache turns caching off; `doctor --json` reports each under `folders`. `host.rs` reads the CPUs and memory the host and its cgroups leave (`cpus`, `threads` with the `CAPTUREFAB_THREADS` override, `memory_budget`), which size the encoder pool, FFmpeg threads and the burst queue. `media/bundled.rs` extracts the embedded FFmpeg once per user to the cache, else `<runtime>/cache`, else `$TMPDIR/capturefab-<uid>/cache` (noexec mounts skipped), shared across processes and trusted by a `verified` marker instead of re-hashing. `inspect` previews go to the private `<runtime>/inspect/` folder (0700, newest 64 files / 64 MiB). Settings a worker emulates for its camera (a simulator's registers, a webcam's video mode) are kept in `<runtime>/settings/` (`engine/emulated.rs`), so a `set` holds for later commands until the runtime dir is cleared, as a real camera keeps its settings until power-off.

FFmpeg: `build.rs` never builds FFmpeg. It embeds one (zlib-compressed, extracted to the cache dir on first use) from `CAPTUREFAB_FFMPEG_BINARY` when that is set at build time, in any profile, and otherwise in release builds only from `target/ffmpeg/<target>/bin/ffmpeg` when that exists; debug and test builds embed nothing, which keeps them small and quick to link. `CAPTUREFAB_FFMPEG_LICENSE` supplies the notice `licenses` prints. At runtime FFmpeg is `CAPTUREFAB_FFMPEG=/abs/path/ffmpeg`, else the embedded copy, else `ffmpeg` next to the executable, else `ffmpeg` on PATH (`doctor` reports which as `ffmpeg.source`); none of them is the typed `ffmpeg_missing` error with an install hint. Media tests requiring FFmpeg are `#[ignore]`d; run them with `CAPTUREFAB_FFMPEG` set and `-- --ignored`. `scripts/build-ffmpeg.sh` builds the pinned, checksummed GPL FFmpeg; `scripts/release.py` packages releases and refuses to build without it. On macOS `build.rs` links `assets/Info.plist` into the executable's `__info_plist` section (camera and local network usage strings); keep its `CFBundleIdentifier`, which existing camera permissions are stored under.

## Architecture

**CLI.** `main.rs` calls `lib::run`, which dispatches the hidden `__worker` argv to `session::run_worker`, `__gentl-helper` to the isolated GenTL consumer (`gentl` feature), `__jpeg-helper` to `jpeg::helper::run` (Unix, with the `nvjpeg` or `vaapi` feature) and everything else to `cli::main` (parse, then `cli::run`, then print and exit). `src/cli.rs` holds global flags, dispatch and routing; `src/cli/` has one module per command family (`camera` for list/info/features/get/set/exec, `capture`, `record`, `inspect`, `auto`, `preset`, `jobs`, `session`, `serve`, `login`, `onvif`, `network`, `doctor`, `debug`, `schema`, `watch` for live measurements, and `shell` with `shell/complete.rs` for the prompt and the line-per-command batch mode), plus `args` (camera selection, durations, times), `paths` (client-side path and template resolution: a path belongs to the caller even when a session does the work), `output` (the only place that prints results and errors), `signals`, and `term` (TTY detection, the status line a slow command shows, the camera picker and frames drawn inline for `--show`). The `shell` feature adds line editing, history and completion (rustyline); without it the shell reads plain lines. `controls.rs` parses feature names, banks (`TriggerMode[FrameStart]`) and the canonical controls (`exposure`, `gain`, `fps`, `roi`, `format`, `trigger`, `auto_exposure`, `auto_wb`). `naming.rs` renders output templates; `context.rs` holds capture tags.

**Process model.** Each camera runs in its own worker process (a re-exec of the same binary, overridable via `CAPTUREFAB_EXECUTABLE`) that leads a process group (Unix) or runs in a job object (Windows) with everything it starts. `session::SessionHandle` / `Coordinator` holds one `session/worker.rs` `Worker` per camera and speaks the protocol of `session/protocol.rs`: newline-delimited JSON requests on the worker's stdin; `hello`, then `accepted`, `started` (with a budget the hang watchdog counts from), events and `reply` lines on a private copy of its stdout, each with a sequence number. Frames never cross to the coordinator: the worker saves captures itself (`engine/saver.rs`, an encoder pool), measures inspections there (`engine/inspector.rs`) and writes an image captured to stdout to an inherited pipe (direct) or a private file in `<runtime>/out` (session). Inside the worker, `engine::WorkerHandle` runs one thread that exclusively owns the `camera::Camera` (and its transport), recordings and scheduled capture jobs (`scheduling.rs`); `engine/history.rs` checkpoints values so a preset apply or an auto change rolls back on failure (a multi-value `set` rolls back in `controls.rs`: what it wrote, in reverse, then any of the image geometry group, `controls::GEOMETRY`, that a write clamped or rescaled), `engine/lock.rs` takes the advisory camera lock, and `engine/saved.rs` reports saved files. Without a session, a command starts its own coordinator and worker in-process, so direct and session commands share one code path.

**Sessions and jobs.** `serve --name X` (foreground) and `session start` (a detached `serve`) run an `ipc::Server`: loopback TCP, token-authenticated, with a descriptor file in the private runtime dir. Clients send the same `SessionCommand`s through `ipc::call`. A camera command uses a session when `--session` names one or a running session holds the camera; otherwise it keeps its camera warm in the implicit `auto` session (started on demand, released after 60 s unused, `--keep DUR` to change it), and `--keep 0`, `CAPTUREFAB_KEEP=0` or `--no-session` give it a worker of its own, as does a host without a writable runtime dir. `--background` leaves a job running in a session. Long operations are jobs (`<session>-<n>`, `session/jobs.rs`), listed by `jobs`: a session saves its jobs in the state dir as they change, so `jobs` and `jobs wait` still answer for a session that has ended, and list a job its session died during as `lost`. The CLI waits on a job's changes with the session's `wait` request (`<seq>`-numbered, at most 25 s a call) rather than polling; `debug rpc` sends any `SessionCommand` (`{"op":...}`) by hand.

`frame/bicolor.rs` handles standard BiColor RGBG/BGRG 8/10/12 unpacked and 10p/12p packed codes. Packed10p requires even source width; packed12p allows any positive width. Keep row-local horizontal phase and view bounds, count only received pairs for native clipping, and normalize each 16-bit component rather than the whole 32-bit pixel. `timeseries/ethernet_ip/logix_bits.rs` reads explicit Logix DWORD/packed BOOL values; element counts and symbolic indices use DWORD units, with the existing shared poll budget and deadline.

**Camera layers.** `types.rs` defines the `RegisterIo` and `Backend` traits (xml/start/next_frame/stop) and `types::Categorized`, the typed error category. Implementations live in `transport/` (`gige.rs` GVCP/GVSP, `usb.rs` U3V via `nusb` behind the `usb` feature, `simulator.rs` with `simulator/replay.rs`, and `gentl.rs` with a bounded native CTI helper behind `gentl`), while `media.rs` (+ `media/v4l2.rs`) provides FFmpeg-backed sources (host webcams, RTSP/SRT, files) and recording with encoder probing, including the Jetson GStreamer encoder. Decoders hand over frames in the format FFmpeg decodes to, as raw video whose format, range, matrix and size FFmpeg's info log line describes (`media/native.rs`; a layout Capturefab does not carry as decoded reopens the source for RGB24 PPM, as `sim:replay` always uses), and decode compressed live sources in hardware where a probe proved the method (`media/hwdec.rs`, `CAPTUREFAB_HWDEC`, with a per-source software fallback); under `auto` only a session's camera workers do (`session::served_session`), whose decoder runs on between commands. A Motion JPEG source is read as the JPEGs it sends (`-c:v copy -f mjpeg`; `media/mjpeg.rs` cuts them apart and decodes them with libjpeg-turbo into the layout FFmpeg would), each frame keeping its JPEG in `Frame::jpeg`, which a default-quality JPEG still stores as it is (`frame::encode_parts`, `passthrough`); a stream is found to be one on its first launch and opened again. A recording of an H.264/HEVC source copies its video instead of encoding frames (`media/copy.rs`, Unix): the decoder FFmpeg also writes what it reads as MPEG-TS to a pipe of its own, a `Tap` cuts it into frames and keeps those since the last key frame, and the recording's FFmpeg only remuxes them through the usual writer. GigE receive on Linux takes up to 32 datagrams a system call (`transport/gige/batch.rs`, `recvmmsg`), each predicted payload packet straight into its place; every message that did not land as predicted is copied out before any is taken in, since one put in its place could overwrite a later one's. Its socket buffer is forced past `rmem_max` where `CAP_NET_ADMIN` allows (`SO_RCVBUFFORCE`). On Linux the frame pipes to and from FFmpeg are enlarged to hold a frame (`media/pipes.rs`, `F_SETPIPE_SZ`, up to 1 MiB), and a frame's own bytes are `vmsplice`d into an encoder's pipe, the frame kept alive until FFmpeg has read it. GigE XML can use camera-local memory or bounded plain HTTP retrieval (`transport/gige/xml_http.rs`), with redirects, transfer/content decoding and one total deadline; HTTPS and HTTP authentication remain unsupported. `genicam.rs` parses GenICam XML (incl. zipped) into a feature node map evaluated live against `RegisterIo`. `camera/register.rs` resolves explicit opaque IRegister `debug read/write --feature` operations, with exact raw hex up to 64 KiB and one deadline across declared selectors, gates, layout, transfer and restoration. Default get/features expose only bounded descriptors, excluded from scalar checkpoints/chunks. Backend deadline-aware memory methods must clip actual physical I/O; the default is Unsupported, and the GigE scope is held only under Control's mutex so heartbeat never inherits it. Raw writes can commit a prefix without rollback or implicit file/LUT commands. `camera.rs` ties discovery, backend and GenICam together; `camera_profile.rs` classifies area scan, line scan, depth, microscope and thermal cameras from what they advertise. `onvif.rs` does WS-Discovery and SOAP profile resolution to an RTSP URI. `network.rs` and `engine/network_defaults.rs` diagnose GigE paths and apply bandwidth sharing. `test_cameras/` holds unauthenticated GigE and ONVIF fakes for unit tests only.

`network force-ip` is a cold local bootstrap utility with one explicit MAC/interface/temporary IPv4 tuple. Its mandatory reservation remains advisory; normal capture locks and retirement semantics are unchanged. Keep one original deadline, selected incoming interface and explicit outgoing source address, one mutation send, fresh matching MAC/configuration discovery and honest post-send uncertainty; never add automatic retries, rollback, controller acquisition or cleanup writes.

Native GigE ownership uses a separate suspend-inclusive lease clock and sticky typed retirement. Every control/resend/cleanup send is gated; completed immutable frames remain saveable. Engine retirement ends frame-dependent work, drains accepted saves, drops the local camera/lock and latches the exact coordinator/worker binding. Only explicit Connect acquires a new epoch; queued requests cannot migrate to it. Worker protocol 6 carries the terminal cause and an in-band connection check. Initial acquisition assumes stable heartbeat configuration; it does not infer ownership from an unqualified late global CCP read.

**Frames and measurements.** Image-with-chunk payloads keep their full original wire bytes and layout in `Frame.chunks` (shared `Arc<ChunkData>`); `Frame.data` contains normalized pixels. Stills publish `.chunks.raw`/`.chunks.raw.json` companions transactionally; video appends successful encoder-input payloads to `.chunks.raw`/`.chunks.jsonl` through storage-backed journals. Network video and stdout captures reject chunked frames rather than silently losing measurements. Saver queues count chunk payloads in their memory bound. `Frame.data` is a `framebuf::FrameBuf`: reference-counted and read-only, so the saver, inspections and a recording share the buffer the camera filled; nothing writes to a frozen buffer. Producers take buffers from the process's `framebuf::pool()` (at most 2 idle, at most 1/20 of `host::memory_budget`), whose recycled bytes are stale: only a producer that writes every byte it delivers may use `take_stale`, and unit tests poison every recycled buffer to catch one that does not. While a GPU JPEG engine is open (`framebuf::share`, held by its `jpeg::helper::Client`, its helper resting included), both pools hand out shared memory segments instead of heap vectors (`framebuf/shared.rs`: a sealed memfd on Linux, an unlinked POSIX shm object elsewhere; build cfg `jpeg_helper`), so the helper reads a frame where the camera wrote it; USB transfers keep heap vectors (`take_vec`). GigE receives payload packets straight into their frame (`Assembler::predict`/`landed`, vectored receive; `CAPTUREFAB_GVSP_SCATTER=0` copies as before); USB3 Vision takes a transfer's pooled buffer as the frame where one transfer holds a whole image (`Layout::whole`), else assembles by copying. Formats a consumer cannot read as they are are decoded a row at a time (`frame/rows.rs` `RowReader`: 8-bit gray or RGB exactly as `convert`, packed rows unpacked one at a time, a mosaic of any depth demosaicked from a ring of three 8-bit rows) straight into what reads them: a preview's box filter, a still's one buffer from `framebuf::transforms()` (a pool of its own, one idle buffer per encoder thread), a recording's scratch. `frame/view.rs` `FrameRef` is a frame or a region of one read in place, so inspections and auto exposure measure regions without cropping. Stills are `frame::encode_parts`: a body that borrows the frame where the format keeps its bytes (raw, Mono8 PGM, RGB8 PPM), plus one insert (PNM header, JPEG COM), written with vectored writes by `storage::save_parts` and stdout. JPEG goes through `jpeg/backend.rs` (`CAPTUREFAB_JPEG`): libjpeg-turbo encodes RGB8/BGR8/Mono8 in place, other color formats from JFIF Y'CbCr 4:2:0 planes written once from their rows (full-range planar 4:2:0 from its own planes), and its output stays in its own buffer; a hardware engine (on a thread of its own with deadlines to open and encode; a GPU engine's helper stops after a minute unused and starts again for the next frame) takes frames once checked against libjpeg-turbo for each size, format and quality (under `auto` on a thread of its own beside the first frame, which the CPU encodes; a check that finds it less faithful is repeated on later frames, a frame it declines goes to the CPU, and one that fails is turned off with a warning on stderr). `jpeg/videotoolbox.rs` runs in the worker and takes color frames, writing NV12 from the rows straight into its IOSurface and keeping the JPEG in its sample buffer. On Linux `jpeg/nvjpeg.rs` and `jpeg/vaapi.rs` run in `capturefab __jpeg-helper` (`jpeg/helper.rs`), started by the worker, which loads the vendor libraries with dlopen and gets each segment's descriptor once over its control socket (SCM_RIGHTS) and then one JSON line per frame naming the frame's segment and an output segment for the JPEG; a segment lent to it is not reused until it answers or has been reaped, and one that misses its deadline is killed. nvJPEG page-locks a frame's segment once and reads it in place (Jetson) or by one DMA, converting other formats once into page-locked JFIF planes; VA-API makes an aligned Mono8 frame's segment a USERPTR surface and writes other frames once into a derived image. Recordings hand FFmpeg a `media::Payload` of the shared frame, converting only what FFmpeg cannot read, once, on the writer thread; only RGB sources go to NVENC/AMF as RGB, a mosaic is demosaicked to RGB24 before any 4:2:0 encoder input (faster than swscale's direct path), FFV1 stores a mosaic as gray, and encoder probes are keyed by the input pixel format. Every copy site calls `copies::record` with its class (boundary, necessary, transform, avoidable); with the `copy-audit` feature a counting allocator and reports in `$CAPTUREFAB_COPY_REPORT` from each worker and GPU JPEG helper (`worker-PID.json`, `helper-PID.json`) back `tests/copies.rs`. `frame.rs` (with `frame/formats.rs` for the low-bit, signed, wide/planar/packed/alpha RGB, 565 and YUV/YCbCr layouts, including planar and semiplanar Y'CbCr with Capturefab's own custom-bit codes where PFNC has none) converts every common PFNC pixel format and encodes PNG (16-bit gray for monochrome wider than 8 bits, packed or not), PGM/PPM and raw; exposure, metering, clipping and focus read packed mono/Bayer and wide RGB samples where they lie, without a full-size intermediate image. `transport/gige.rs` normalizes continuous LSB packing to byte-aligned rows when the payload length shows it. The pixel-format table is in `docs/camera-compatibility.md`. `jpeg.rs` wraps libjpeg-turbo (`jpeg` feature); `videotoolbox` adds Apple's JPEG engine, `nvjpeg` and `vaapi` the GPU encoders (`CAPTUREFAB_CUDA_LIB_DIR`, `CAPTUREFAB_VAAPI_DEVICE`, which `media.rs` also gives an explicitly named `*_vaapi` FFmpeg encoder, one `record` never asks for; the VA-API helper keeps libva's messages for its errors, since the worker passes the helper's stderr on to the user). `inspect.rs` measures exposure, clipping and focus and renders the bounded preview; `auto.rs` runs the host auto-exposure loop. `tests/frame_golden.rs` pins their outputs against `tests/golden/frame.json`. It and `benches/runtime.rs` reach these internals through `capturefab::testing`, which only the `testing` feature builds (tests and benchmarks turn it on through a dev-dependency on the crate itself), together with the reference conversions (`frame::rgb`, `gray8`, `rgba`, `unpacked`) and one-call wrappers nothing else calls; mark such an item `#[cfg(any(test, feature = "testing"))]`.

Frame queue limits charge the complete backing allocation of pixels, retained JPEGs and chunk payloads through `Frame::buffer_bytes`, including unused capacity and shared-memory pages. Preserve logical wire and stored byte counts separately: a short USB frame can retain its maximum-size receive allocation without copying.

**Industrial data.** `cli/data.rs` exposes `data record --config JSON --for DUR -o PATH`, `data export` (CSV/JSONL), and `data protocols`. `timeseries.rs` owns the version 1 JSON configuration, bounded per-source acquisition threads, shared host-monotonic receive clock, Header/Sample/End JSONL recording format, failure/interruption recovery and streaming export validation. `timeseries/modbus.rs` implements read-only native Modbus TCP, serial RTU and serial ASCII (Unix terminals or Windows COM ports), with per-signal serial station selection; `timeseries/s7.rs` implements classic read-only S7 absolute scalars/contiguous typed arrays over ISO-on-TCP, with bounded PDU segmentation, packed standard-layout BOOL ranges and explicit DATE/TIME/TOD/DT/DTL/LTIME/LTOD/LDT layouts. Its private temporal decoder preserves raw bytes, exact duration/fractions and invalid application states without inferring a clock basis; `timeseries/ads.rs` reads Beckhoff ADS direct addresses and cached symbolic handles; `timeseries/hart.rs` reads universal HART process values through a preconfigured Microflex 101-0035 managed serial modem; `timeseries/yokogawa_fam3.rs` reads native FA-M3 PC Link TCP bits and words in binary or ASCII; `timeseries/fatek_fbs.rs` reads configured FBs standard Port0 command44/46 bool/native16/native32 scalars and arrays over fixed7E1 serial or an explicit transparent TCP bridge; its private parser preserves literal native and combined W/DW views without inferred bit labels, while failed polls remain atomic and permanently retire their owner. `timeseries/ls_cnet.rs` reads configured XGB dedicated Cnet serial rSS scalars and explicit-address arrays with mandatory BCC, native integer widths, one poll deadline and permanent retirement; keep its default partial-cutoff failure strict and do not infer disputed rSB framing or address progression. `timeseries/ls_xgt.rs` reads LS ELECTRIC XGT/XGB direct variables and typed byte-backed arrays over configured FEnet TCP; `timeseries/slmp.rs` reads Mitsubishi SLMP 3E binary or ASCII TCP devices and `timeseries/mc_1e.rs` reads MELSEC-F MC 1E binary or ASCII TCP devices; `timeseries/fins.rs` reads Omron FINS memory areas over TCP with node negotiation or UDP with configured node addresses, with explicit byte/word order. `timeseries/fins/host_link.rs` reads serial C-mode RD and direct FINS FA with per-signal station selection; `timeseries/iec62056_21.rs` reads configured OBIS fields in optical IEC 62056-21 Mode C sessions with a bounded baud change, explicit parity and optional unchecked readout; `timeseries/can.rs` passively receives Linux CAN/CAN FD and explicit typed signal maps; `timeseries/ifm_iot.rs` reads one ifm IoT Core IO-Link port per source with raw bytes and explicit typed mappings, optional verified TLS and environment credentials; `timeseries/sick_cola.rs` polls explicit CoLa A or model-specific CoLa B; its private ASCII and binary model decoders retain bounded independent channels and exact raw/status/clock fields; `timeseries/velodyne_vlp16.rs` shares passive VLP-16 and explicit HDL-32E UDP profiles in synced immutable groups with original host clocks and explicit committed-prefix recovery; ## CLI contract

The CLI is a public, versioned automation contract (`capturefab schema`, `web/reference.html`, `web/agents.md`, `web/llms.txt`):
- `--json` prints exactly one single-line JSON document on stdout: the result on exit 0, `{"error":{"code","message","hint"?,"details"?}}` otherwise, also for usage errors. Results never contain a top-level `error` key; partial work of a failed command goes in `error.details`. Diagnostics go to stderr.
- The exit code is the category (0 ok, 1 failed, 2 usage, 3 unavailable, 4 timeout, 5 unsupported, 6 storage full, 130/143/129 interrupted); `error.code` is the specific reason. Both come from typed errors (`types::Categorized` plus reason), never from message text, and survive worker and session IPC hops.
- Keys are snake_case with units in names (`exposure_us`), no null values, RFC 3339 UTC times, bounded lists with `truncated`.
- Credentials in URLs must be redacted (`media::redact_url`, `scrub`) in output, logs and errors.

When changing commands or output shapes, run `python3 scripts/site-reference.py --binary target/debug/capturefab` (CI fails when `docs/cli-schema.json` differs from the binary), and keep `README.md`, `web/agents.md`, `web/llms.txt` and `web/docs.html` consistent; then `python3 scripts/docs-search.py`. Avoid publishing camera testing results or compatibility claims while the software is under rapid development.
